# LiquidityMapperFast agent instructions

## Language and checking

All authored application code, scripts and tests are strict TypeScript: `.ts`/`.tsx` (browser, shared) and `.mts` (Node ESM). Keep the three compiler projects strict (`tsconfig.json` browser+shared, `tsconfig.node.json` server, `tsconfig.tools.json` scripts and tests); do not enable `allowJs`/`checkJs`, add blanket `ts-nocheck` or broad `any` casts. Type annotations do not validate exchange frames, HTTP bodies or storage: validate at those boundaries at runtime.

Permanent non-TypeScript exceptions: generated build output (`dist/`, `build/`), the generated WASM glue in `src/app/wasm/`, and the Rust kernels below.

## Rust/WASM compute kernels (approved exception, 2026-10-04)

Compute-bound inner loops (heatmap rasterisation, level grouping) live in `crates/hlm-kernels`, compiled to WebAssembly with wasm-bindgen. Rules:

- Kernels are pure functions over flat typed arrays; JavaScript owns all state, validation and I/O. A kernel holds no state between calls, touches no DOM and parses no exchange frame.
- Every kernel has native `cargo test` unit tests (`npm run test:wasm`) and a Node contract test (`tests/app-client.test.mts`) that loads the committed wasm and checks it against the server's JS implementation of the same spreading.
- Build with `npm run build:wasm` (needs the `wasm32-unknown-unknown` target and `wasm-bindgen-cli` 0.2.129). The generated glue and `.wasm` in `src/app/wasm/` are committed so a checkout builds without a Rust toolchain; regenerate whenever the crate changes.
- The crate keeps its default `crates/hlm-kernels/target/` (gitignored); create no other Cargo target directories.
- Do not add WASM for work that should not run at all. Memoise or delete first; profile before and after and record the numbers in `docs/deslop/`.

## Performance and memory

The earlier byte-accounting "admission/lease/grant/reservation" machinery was measured as the dominant CPU cost on both client and server and was removed (`docs/deslop/baseline-2026-10-04.md`). Do not reintroduce per-message or per-frame memory estimation, cross-tab byte leases or response-size reservations. Bound memory structurally: ring buffers, fixed retention windows (`RETENTION_MS` in the recorders), capped frames.

Measure with an isolated, visible-state headless Chrome over CDP. A tab reporting `visibilityState: hidden` has throttled timers and rAF; its numbers are meaningless. Use the real GPU path for WebGL timings (software GL says nothing about GPU frame time).

- A feed restart must never leave the server without feeds. `LiveFeedManager.start()` retires every old feed before its metadata requests, so an error in between used to leave a running manager with no feed and nothing to reopen one (12 hours of frozen candles and seven stopped venues, 2026-10-06; `docs/deslop/feed-recovery-2026-10-06.md`). `start()` now schedules a recovery with the last configuration that finished, a watchdog (`checkLiveness`) catches a start that hangs or a manager with specs and no feed, and `/api/diagnostics` reports `feedManager`. Keep new work between retire and open inside that guard, and keep recovery and watchdog timers `unref`ed.
- **Zoomed out over days** (`docs/deslop/zoom-out-2026-10-09.md`). The server merges minute columns into wider windows in flat arrays (`mergeWindow` in `shared/recorder.ts`, equal to the old map merge to the last bit; keep the test) and keeps windows that have ended; the page asks for column steps that double (`hub.loadColumns`) so zooming reuses them. A merge on the request path blocks every other request: measure one before adding it. Anything a pane asks the worker for is keyed by what changes its answer, never by the view to the millisecond (a map following the live edge moves every frame): the depth pane counts whole columns (`depthKey`) and refreshes what is live on a clock, the raster is redone no more often than three times its own duration. A frame that only moves the pointer must not judge or regroup data: absorption keeps its judged marks until the groups or thresholds change and its squares until the map moves a pixel. No blurred shadow drawn per item per frame (the whale glow is a cached image, `glowOf`).

## Phones and tablets

- Two attributes on `<html>` (`src/app/device.ts`, tested in `tests/app-device.test.mts`) drive the touch arrangement: `data-layout` (`phone`, `phone-landscape`, `desktop`: how the panes are arranged) and `data-bar` (`compact`, `full`: how the controls are). Put mobile CSS in `src/app/mobile.css` under one of them (or `(pointer: coarse)`), never in a user-agent test, and keep the desktop rules in `styles.css` unchanged. Script that must differ reads `isPhone()` / `compactBar()` / `isCoarse()` from the same module.
- A phone must not write the desktop's saved layout (`hlm-layout-v2`): `Layout.#persist` returns early when `isPhone()`. The dock's own sizes use `hlm-dock-size`.
- Touch gestures come from the pure recogniser in `src/app/touch.ts` (tested with a fake clock); panes bind it with `bindTouch` and leave mouse and pen to their existing handlers. A pinch is reported per axis (`axisPinchScale`).
- Test by emulation: Chrome over CDP with `Emulation.setDeviceMetricsOverride { mobile: true, deviceScaleFactor: 3 }`, `Emulation.setTouchEmulationEnabled`, `Input.dispatchTouchEvent`, and `Emulation.setCPUThrottlingRate` for a slow phone. Check portrait, landscape (844 x 390), a small phone (360 x 640) and a tablet (820 x 1180 and 1180 x 820). It is Chrome, not Safari; say so when reporting.
- Never let a floating panel, menu or dropdown rely on `position` computed from its anchor on a touch screen: they are bottom sheets there (`ui.ts`, `menu.ts`, `sheet.ts`).

## Words and look

- Every sentence a person reads goes through `t('...')` (or `tn(n, 'one', 'other')` for a count) from `src/app/i18n.ts`; English is the key and `{braces}` mark values. `tests/app-i18n-packs.test.mts` fails on a text left outside `t()` and on a pack missing it, so add the text to all eleven packs in `src/app/i18n/` (`npm run i18n:template -- xx` shows what a pack needs). `boot.ts` loads the language before `main.ts`, so top-level `t()` is fine in the page's own modules, but code that runs in a worker must not rely on it. Status text that code parses (`stateOfStatus`) stays English. Details: `docs/languages.md`.
- The guide's text is data in `src/app/guide/content.ts` and the words its pictures draw go through `tg('...')` (`guide/words.ts`); both are translated in `src/app/guide/i18n/<code>.json`, fetched when the guide opens. A change to a guide text or a picture word needs the eleven guide packs updated (`npm run i18n:guide -- xx` writes the template; `tests/app-guide-i18n.test.mts` checks coverage, markup and placeholders), and the guide must still read in ten to fifteen minutes (`tests/app-guide.test.mts`).
- **Lamps.** A button that switches a feature on and holds its settings (Trades, Liquidations, Absorption, Volume profile, Key levels, Highlights, Sound, Range, and the colour range's Auto) wears a small indicator lamp, the `.led-btn` dot in `styles.css`: lit in the bid colour while the feature is on, dim while it is off (Sound adds amber while the browser keeps audio locked, and a ring when one plays). It is part of the retro hardware look this page keeps, so a new on/off feature gets the lamp, set with `data-state` (`lamp()` in `toolbar.ts`), not a pressed look. Such a feature is one button that opens its panel, the panel's first row being its on/off switch: no separate settings button beside it. Buttons that choose what is shown (the pane toggles, timeframes, Spot / Perp / Both) keep the pressed look; a button that only acts (Recenter, Screenshot, Guide) has neither.
- **Help buttons.** Every feature that shows something on the chart has one "?" (`helpButton` in `src/app/help.ts`, its text in `HELP`), and only one: a pane in its header; a feature a toolbar button opens (Trades, Liquidations, Absorption, Volume profile, Key levels, Highlights, Sounds, Range) in its panel's tool strip; a settings window opened from a pane's header shares that pane's. Windows that only do a job (About, Install, the venue menu, the venue and coin pickers) have none. A "?" inside a panel opens its text in that panel, under the tool strip; elsewhere it opens a panel beside the button.
- **Range tool.** The toolbar's Range button and the Select button in the map's top-right corner (beside Recenter, for discovery; both lamps lit while armed or while a selection is shown) arm one drag: on the map it selects a box, on a pane under the map or across the flow column a stretch of time at every price. Ctrl+drag (Cmd on a Mac) selects at any time; Shift is already the map's horizontal pan and the right button its zoom. A selection is snapped once, when the drag ends, to the whole minutes it touches, and every section of its panel is about those minutes and one set of instruments (`flowIds`: the exchanges switched on inside the Spot / Perp filter). The market orders come from one `range()` question to the recording (`shared/footprint.ts`, `/api/v2/range`, the browser engine's `range` call), never from per-frame work; the absorption marks, the resting orders (the worker's `cell` question) and the largest orders are what the map holds and draws. A live selection (one that reaches the open minute) is asked again only while its panel is open and the page is shown, at twenty times the last answer's time (2 to 30 s), and the panel rewrites only the lines that changed (`LineList`). Its panel is opened with `stays` (a press on the map must not close it); another panel opening in its place leaves the selection on the map (the button brings its panel back), and closing it ends the tool. The marks and the large orders are loaded for the map's window only, so a selection reaching past it says so (`partial`). A new pane with a time axis draws `state.range` and hands its drags to the tool (`begin` / `move` / `end`).
- **Volume profile (the traded column) and its levels.** Volume profile is a lamp button, off by default (`show.traded` is its switch; a save from before it had settings reads as off), whose panel holds `state.traded` (`readTraded` checks a save field by field). The point of control and the value area (VAH, VAL) are read with `shared/profile.ts` from every price that traded, on rows of the map's grid step times the Row size setting: never from the column's display rows, which follow the zoom. The column asks the profile on `requestStep` (a step both its rows and the level rows divide), draws its POC and value area at the computed prices, and a drag on it (or a click on a row) is a Range selection of whole display rows over the column's own window (a test asserts the panel equals the bars). Lines for what is on the chart come from the column's answer; days, weeks and sessions from `valueAreas` (`/api/v2/value-areas`, the browser engine's `valueAreas` call): the hub keeps finished windows for good, asks the one under way again after a minute (five when an answer took over 300 ms) and puts at most a day of minutes in a request (a day costs the recorder about 90 ms). Sessions are wall-clock times in their zone and follow its daylight saving (`sessions.ts`, tested on the change days); a window recorded for under nine in ten of its minutes is drawn faint; a naked POC is judged on the chart market's candles with half a row of tolerance. The lines use the palette's `poc` colour (every theme has one), over a halo.
- **Order counts by price.** The footprint recorder counts each market order in the row of the price it started at (a buy's lowest fill, a sell's highest) in minutes begun since counting began; such a minute is stored as five numbers a row, an older one stays uncounted (three numbers), and an order never makes a row without volume (`nearestCell`). Keep `profile` and `query` answering three numbers a row: open pages parse those strictly.
- **Liquidations.** Only Binance (`forceOrder`, its own socket in `Made.liquidations`, at most one per symbol a second: `throttled`), Bybit (`allLiquidation`), OKX (`liquidation-orders`, every swap on one channel, filtered by instId) and Deribit (the `liquidation` flag on its trades) publish them; Hyperliquid, Coinbase and every spot market publish none, and `LIQUIDATION_COVERAGE` in `shared/liquidations.ts` is the one table of that. The side is the position closed (`long` = the exchange sold), read per venue (Binance's order side is the opposite of Bybit's position side; Deribit's M/T flag says whether the maker or the taker was forced). Bybit reports the bankruptcy price (about 0.3 % past the mark on BTC), which the market need not have traded at, so a `bankruptcy` report is drawn at the instrument's last trade if that came within a minute of the liquidation's own time (a report can arrive minutes late: then at its own price, and the box says so), and the box gives both prices. OKX calls its price `bkPx`, but it was measured within a few basis points of the mark, so it is a `fill` like Binance's and Deribit's, drawn where it went. For this the last-trade maps (`lastPrice` in `api.mts`, the engine's `#last`) keep each trade's own time. The server records them from $100 for a week (`liquidations` table, `/api/v2/liquidations`, pushed as `liquidations` on the socket) even for a venue whose book a browser reads, so FlowSources runs a covered venue's liquidation feed alone; the browser engine keeps them in memory only and the panel says so. What a venue does not report is said in the panel (`coverageLines`), never on the chart. A liquidation is also one of the market orders, so the Range line gives its share of all the market volume in the selection's minutes (not of a box's band: it is drawn at one price but traded wherever the book took it) and never adds it; it counts only those from the panel's smallest, and a fill that closed a long and a short (Deribit's MT) once in the share. A selection's panel reads what the map holds again (`refreshHeld`, no new recording question) when the large orders or liquidations arrive or their settings change. Diamonds in the sell colour for longs closed and the buy colour for shorts, as everything else on the page: the shape and its hard edge say forced.
- **Key levels.** The previous day's, week's and month's high, low and middle, each period's open and the high and low so far of the one under way, as lines (`src/app/keylevels/`, off by default; the button is "Key levels" because the order book already has a Levels view). They are worked out from one market's candles read straight from the exchange (`fetchCandles` and `webGet` in `shared/history.ts`, the same in server and browser mode): the server's candle route serves only its own recorded minutes, capped at 400 bars. The candles are hourly, or half- or quarter-hourly in a zone whose clock is that far off the hour (`barMsFor`: India, Nepal, Lord Howe's summer), so every period starts on a bar and none is split. The market is the chart's own where its history can be read (the same instrument: OKX spot under `okx` is not the OKX swap), else the first of a fixed list that lists the coin, and the panel names it (`historyTarget`; a server names Binance spot `binance:BTCUSDT:spot`). `KeyLevelHistory` holds one stretch of bars, reaching back at most `MAX_BACK_MS` (62 days, so the previous month is always held; up to 24 pages a request, which OKX's 100-bar pages need), extends it back only when the chart needs earlier periods, in turns of at most 24 pages while each turn gets older bars, and stops once the exchange has nothing older, asks again for the newest bars every five minutes (`heldTo` is where the last such answer reached), drops bars older than the levels can reach, and waits a minute after a failure; nothing is asked or worked out per frame (the pane keys its caches by the view's hour and the clock's minute). A period's open is drawn when the history held reaches back to its start, and its high, low and middle only when it also reaches its end (`heldTo`, or the chart's own candles running on to now): a missing bar inside it is an interval nobody traded (Coinbase sends none), not a hole, but history that stopped at noon is not a day. After the last bar the chart's own candles (same market, no coarser than the bars) move the period under way. Days and weeks start in the Volume profile's zone (`traded.zone`, shared on purpose so the two never disagree), weeks on Monday, months on the 1st (`monthWindows`). A period's level is drawn only when its candles are complete; a previous level the next period never traded through runs on, dotted, until reached, and once its own period has ended its label carries that period's date and its axis tag is outlined and gives way to the current ones. Tags are placed (`placeTags`) clear of each other and of the live price's tag, never moved off their price, and a grid price under a tag is left out. The colour is the palette's `level` (every theme; the contrast test covers it).
- **Readouts past the end.** A time pane's popup stays on its newest point while the pointer is right of the data or over the pane's price axis (`readAt` in `panes/pane-cards.ts`), and the dashed cursor goes to that point (`cursorT`). A new time pane follows the same rule.
- The window language (shapes, edges, title bars, hard shadows) is `src/app/chrome.css`; its tones come from `chromeFor` in `theme.ts` (never hard-code an edge or face colour, and keep `BEVEL` the one dial). No `backdrop-filter`, blurred shadow or pill shape: they are the costly ones over canvases. Glyphs on buttons are drawn (CSS masks or bars), not typed.
- Canvas popups go through `infobox.ts` (`paintInfoBox`), page-element ones through `hovercard.ts` (for panes too short to hold a box); build their lines in plain functions so tests need no canvas.
- Floating panels are all `openPanel` in `ui.ts` (one open at a time; the nine settings, help and about panels). A panel opens on the side of its button where it fits (`placement.ts`: pure and tested, so change the rules there), keeps that side across redraws, and takes its natural height from `root.offsetHeight` with the maximum height lifted, never from `root.scrollHeight` (once a maximum is set the body shrinks and the root reports the height it was cut to). A person can drag it by its title bar (`drag.ts`, which also moves the venue picker and the guide): a moved panel is pinned (an outside press no longer closes it; it closes on the x, Escape or its button), is clamped and not re-anchored when it redraws or the window changes, and on a compact bar every inline position it left is cleared. The drag listens on the window and does not rely on pointer capture alone. Menus, tooltips, hover cards, toasts, phone sheets and the screenshot editor are not windows and are not dragged.
- **Flow history.** The page holds flow a second at a time for at most a day (`HISTORY_CAP_MS`, a ring of 2^17 s); a window reaching further back (the Map span over days) draws that part from minutes (`/api/v2/flow-minutes`, `FlowRecorder.minutes`: buy, sell, last price and the running delta's low and high per minute, from memory and then the store, which keeps a week). `cvd/track.ts` joins them: the minutes are shifted to meet the seconds at the first whole minute the seconds hold, and a window inside the seconds reads only the seconds. Ranking, the quiet flag and the dot rows (`counted`) count seconds alone; the aggregate lines also count an instrument that has only older minutes (one with seconds takes its family's place first). `flowWindow`'s `earliest` is the track's first second, so "Flow recorded since" means recording began then; a source with no minutes (the browser engine, an older server) says older flow is not available instead.
- The dot rows above the flow column (`cvd/strip.ts` is every number and word, `panes/cvd-strip.ts` the canvas) are an element of their own, never part of the column's canvas (`rowHeights`, `locateRow` and the scroll would all have to change). They count `CvdModel.counted`, the instruments of the ALL VENUES row, so a one-hour flow row equals that row. The size rows need the footprint statistics in **one** `source.sizes(ids, windows)` call (never split: the minutes two answers saw cannot be added; the server counts minutes on its own clock), checked field by field with `parseSizes`; a source that cannot answer (an older server) leaves the flow rows working and says so in the size rows, asking again once a minute. A window recorded for under nine in ten of its minutes is marked (a hollow amber ring, never a filled amber lamp: Colour-blind's sell colour is close to that amber). The one blink is the leading lamp of a size row when `hub.onPrints` delivers a trade of that size (the handler in `main.ts` chains `sounds.feed` and `cvd.flash`; a hard 4 px ring like the Sound button's, no blur, none with `prefers-reduced-motion`). Settings of the strip alone (`CvdSettings.strip*`) must not re-rank the exchange rows: `CvdPane.settingsChanged` compares `rankingKey`. Not on a phone layout.
- The order book's Compact mode splits each level's bar into the venues that make it up (`panes/ladder-pieces.ts`, pure and tested): one piece per venue in a held order (the most liquidity on the rows in view first, kept for five minutes while the venues stay the same, so a venue keeps its place down the column), the shade alternating with the order, a piece too narrow to see joined to the smaller venues' piece at the end, and a label inside a piece wide enough (name and size, or a code from `VENUE_CODES`: no two venues share one). Drawing and the pointer read the same `barPieces`; the level's popup names every venue in Compact. Aggregated keeps its venue columns and its tinted bar.
- **Venue marks.** An exchange is shown by our own mark (`src/app/venue-marks.ts`): its initials in its brand colours on a small square, spot markets with a corner notch. They are drawn, never logo files or another project's icons (those carry their own licences). One table, `VENUE_MARKS`; a venue missing from it gets a grey square with two letters of its name, and a test keeps every pair of colour and letters distinct and the letters readable (contrast at least 3). A canvas draws one with `drawVenueMark` (a cached bitmap per venue and size: cheap in the bubble loop), the page with `venueMark` (the letters are the CSS `::before` of `data-mark`, so the element's text stays the venue's name alone). Spot-ness comes from the market list (`useMarkets`), not only a "spot" venue alias: most spot markets have none. They stand in the venue chips and menu, the flow column's row names, the bubbles (`BubbleSettings.marks`, with the bubble hover that dims every other venue), the order book's Compact pieces, Aggregated column heads and single-venue title, and the Range panel's exchange rows; a popup line takes one with `InfoLine.mark`. A new place that names a venue uses the same mark.
- The order book's zoom is a price step per row (`panes/ladder-zoom.ts`, the `GROUPS` list: each step regroups the book 2 to 2.5 times). The wheel goes through `ladderWheel()` (at most four steps a second for clicks, three for a touchpad, one step per event however many clicks a browser folds into it: a free-spinning wheel or a long swipe once threw the zoom from 20 to 1000), and the wheel, a drag on the price column and the touch drag share one anchor rule, `holdsMark`: while the book is centred on the mark (and Alt is not held) a zoom holds the mark on the middle row and passes the mark as it is at every step, never the price captured at the start (BTC moves while the hand does); once the book is scrolled, or with Alt, it holds the price under the pointer. A new zoom input must use both.
- Do not write the DOM on every pointer move unless the value changed: assigning the text a node already has still invalidates style and layout. Header readouts use `setHtml` / `setText`, which write only on change. Measure with CDP `Performance.getMetrics` (see `docs/deslop/performance-2026-10-05.md`).

## Running and verifying

- `npm run dev` builds and starts the live server on `http://127.0.0.1:8787` (a page it serves uses it as its data source); `npm run dev:client` runs the page alone, reading the exchanges from the browser; `npm run build:site` builds the static site; `npm run dev:fixture` runs offline. Before starting or restarting a local service, inspect existing process and port ownership; test on a spare `PORT` rather than stopping someone else's server.
- `npm test` builds and runs the Node suite; `npm run typecheck` runs the three strict projects; `npm run build` does both plus the Vite bundle.
- Visual inspection: compare against `example_images/` (a local folder that is not in git: reference screenshots for the heatmap, order book and footprint, plus `bookmap.PNG`, the Bookmap reference for the colour ramp and the Liquidity Tracker row). Heatmap, profile, ladder and footprint spacing, intensity and grouping follow those screenshots.
- All implementation and evidence artifacts belong in this repository. `Aggr_Trade` is a read-only reference.
- Do not edit source, configuration or served output during an acceptance measurement run.
