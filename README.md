# LiquidityMapperFast

**Open it: https://liquiditymapperfast.github.io/** — free, no sign-up, MIT licence. The **Tour** button inside shows you around in a minute, and the **Guide** explains everything.

A market-map workbench for one coin at a time across many venues: BTC, or any of about 150 coins listed on most of them (see Coins below). It runs entirely in the browser: the page reads the exchanges' public feeds itself, in a Web Worker, so it works from any static host (GitHub Pages included) with no server. A local server remains as an optional source with a week of recorded history. The workbench draws a liquidity heatmap built from recorded order-book depth, a price profile, an aggregated order-book ladder, depth and open-interest panes, and a footprint of executed volume. The look follows the reference screenshots in `example_images/` (a local folder, not in git); a right-hand profile column and an OI row complete it.

The default venues are the largest ones whose public order book is also deep, fresh and reliable: Binance, Bybit, OKX, Bitget, Hyperliquid and Deribit perpetuals, plus the spot markets of Binance, Coinbase, Bybit, OKX and Bitget (`Research_Findings.md` has the measurements and the rule; Gate.io and MEXC are big by reported volume but are left shallow on purpose: Gate.io publishes no book beyond about 15 bp and reports about twice the volume it was seen to trade, and MEXC's deep book is three to five times Binance's near the price on a quarter of its trading, so it would dominate the map; see the 2026-10-12 section there). **In the browser** the Venues picker offers these eleven and MEXC, which is off until chosen: a page can read only its best 20 levels (its REST sends no CORS header), and its resting book is several times heavier than its trading (`Research_Findings.md`, 2026-10-08). Each has a connector in `src/shared/venues.ts` and the choice is kept in this browser's localStorage. **With the local server** the picker offers 29 (the 20 feed venues plus the spot markets of Binance, Bybit, OKX and Bitget, and Binance US, HitBTC, Poloniex, BitMart and Bitunix, which run on small self-contained connectors) and up to 32 feed venues can be enabled; its Recommended button ticks the default set, and nothing changes until Apply. The choice is saved beside the history database (`v2-feed-venues.json` for the feed venues, `v2-venues.json` for the connector venues) and restored when the server restarts, so an existing install keeps its venues until Recommended is applied (a recommended venue added by a later build starts once, in the browser and on the server, since the saved choice records which venues it had seen); on the first run the recommended venues are selected (`HLM_DEFAULT_VENUES=all` selects every supported venue and starts every connector, `HLM_DEFAULT_VENUES=configured` keeps the venues set by the `*_ENABLED` flags and starts no connector venue instead). A fresh start needs about 30 s before market metadata allows the selection to apply. Everything reads public exchange feeds from your own machine (the browser, or the local server); no order is placed and nothing is sent to any service of ours. Optional HyperTracker credentials stay on the server, which is why those layers are listed as upcoming in the browser-only page.

## Run

```powershell
cd HyperLiquidMap
npm install
npm run dev:client   # the page alone, reading the exchanges from your browser: http://localhost:5173
npm run build:site   # typecheck + the static site in dist/ (HLM_SOURCEMAP=off leaves out source maps)
npm run preview:site # serve dist/ to look at it
npm run dev          # build + local server with a week of recorded history on http://127.0.0.1:8787
npm run dev:fixture  # the server with offline demo feeds
```

**Which source the page uses.** A static host has no server behind it, so the page reads the exchanges itself (`src/app/browser-source.ts`, the engine in `src/shared/engine.ts` running in `src/app/browser/feeds.worker.ts`). Served by the local server, the page finds `api/v2/state` on its own origin and uses the server instead, with its recorded history. `?source=browser` or `?source=server` forces one; `?persist=0` stops a browser session from keeping recordings. The browser keeps the last 24 hours of recorded depth, executions, large trades, liquidations and open-interest readings in IndexedDB, written by one tab at a time (a Web Lock), and the heatmap marks where its recording begins: a page can only record while it is open. The engine starts on the live feeds at once and reads those recordings, and the recorded history of the day before, meanwhile: the book, the price, the trades and the flow move within a couple of seconds of opening, and the heatmap's history (with the other recorded panes) fills in when it has been read. A returning page reads the map's last three hours first (about a fifth of a second, where the whole day takes three) and draws the window it opens on from them; the rest of the day comes with the other panes. Before that day the heatmap's depth comes from the long history (BTC, from 2026-11-01 on, kept for good): the history service folds every book's minutes into windows of 2 to 4,096 minutes as the page merges them and serves them as tiles, so a view that reaches before the page's own day draws its columns at two minutes or coarser from them, fetched for the view as it moves; the page's own minutes take over where they begin (`src/app/archive/`). ETH and SOL have heat-map history too (a trial, from when the service began recording their books): the service records their books as tiles alone, from 8-minute windows up, so their views before the page's day draw at eight minutes or coarser (the finest level the service's `latest.json` names for the coin), a live view too until the tab has recorded the whole of it (their hours bring no book minutes for the day). Depth only: the flow, trades and footprint keep the day. See `docs/deployment.md` for publishing.

`PORT`, `HISTORY_DB` (SQLite; the depth recorder writes `depth-v2.sqlite` beside it) and `QUOTA_FILE` choose where state lives. To try a change without disturbing a running instance, start a second server on another `PORT` with its own `HISTORY_DB`. The server answers only requests addressed to `localhost` or an IP address and, for a browser, only from its own page, so another website you visit cannot drive it (`HLM_ALLOWED_HOSTS=name1,name2` adds public names for a deliberate deployment; `docs/deployment.md` covers going public, GitHub Pages and what can be protected). `HLM_SOURCEMAP=off` leaves source maps out of a published build.

`npm test` builds and runs the Node suite, `npm run typecheck` runs the three strict TypeScript projects, `npm run test:wasm` runs the Rust kernel tests, and `npm run build:wasm` regenerates the committed WASM glue (needs `wasm32-unknown-unknown` and `wasm-bindgen-cli` 0.2.129).

## Using it

| --- | --- |
| Wheel on the chart | Zoom time and price together, by the same factor, so the picture keeps the shape you gave it (a limit on one axis stops both, and only the turn that would go past it: a chart framed wider than the price limit is held by a turn out and zoomed by a turn in, never driven the wrong way): about the live edge and the current price while the map follows the market (so it swells and shrinks around them instead of sliding), about the point under the pointer on a map you have moved by hand. Alt holds the pointer too, and takes the map off the live point as a drag does (else the current price would pull the scale back from under it). The wheel on the time labels along the bottom zooms time alone |
| Wheel or drag on the price scale | Zoom the price axis about the current price while it is on the map (the pointer turns to a resize arrow over the scale; the wheel over the profile column beside it zooms price too); drag up zooms in, down zooms out; Alt + wheel zooms about the pointer (and takes the map off the live point) |
| Shift + wheel | On the chart, zoom time alone (what the wheel did there before it zoomed both), held as the wheel holds it; on the price scale, time instead of price |
| Drag / Shift+drag | Pan both axes / time only |
| Double-click, `R`, `Home`, Recenter | Return to the live edge |
| Go to (map corner, `G`) | A date and time on the page's clock: the map is centred on it at its zoom (and fitted to the candles there). It says how far back the depth and the candles go (the chart holds its last 500 candles: at 1m that is about eight hours, so further back the candles are the exchange's history, read for the view, with the depth and footprint the recording has); an earlier moment goes to the start of them, a later one to the live edge |
| Replay (Go to → Replay from here) | Plays what was recorded back as if it were live, from the moment chosen, at 1×, 10×, 60× or 300×, with a bar on the map (pause, speed, the moment, Live). The map, its candles (the one under way rebuilt from the recorded price a second), the trades, the panes under it and the flow column show what was known then; what came after is covered. Not shown: the order book (recorded only as the map's minute columns), the profile column and the dot rows; the footprint, bar statistics and open interest of a candle appear once it has ended. Sounds and alerts are silent; a replay that catches up is live again |
| Price line | The dashed line at the last price and its tag on the price axis are in the colour of the candle under way (rising or falling; the order book's price row too), and under the tag a box counts down to the candle's close (UTC-aligned, as the exchanges close them) |
| Layouts (the map's corner; Settings on a tablet) | Arrange the panes, choose a ready-made layout or keep your own. Applying a layout, hiding a pane and deleting a layout offer Undo, which puts back what that changed (the panes if nobody has moved them since, and each setting a saved layout carried that still stands as it left it) and leaves what you did in the meantime. Kept in this browser. On a shorter window the panes under the map shrink in proportion so the map keeps at least 30 % of the column (and its own minimum), and get their heights back on a taller one; this also applies when the window is resized. See *Layouts and the places of the panes* below |
| Keys (Keys in the status bar, or `?`, lists them) | `1`–`7` the timeframes 1m to 1d, `R` / `Home` recenter, `+` / `−` zoom time, `F` `T` `L` `A` `P` `O` `K` `V` `H` switch Footprint, Trades, Liquidations, Absorption, Volume profile, TPO, Key levels, VWAP and Highlights on or off, `U` folds the TPO into its profiles or lays it out in time, `X` arms Range (`Esc` cancels), `D` the drawing tools (Delete removes the drawing selected, Ctrl+Z / ⌘Z undoes, Ctrl+Shift+Z or Ctrl+Y redoes), `S` screenshot. Not while typing in a field or a window is open, nor with Ctrl, Alt or ⌘ held (but for Undo and Redo) |
| Right-drag | Right / up zoom the time / price axis in; left / down zoom out |
| Order book: wheel, drag the price column, drag the book, double-click | The wheel zooms the book about the current price (Alt + wheel, or a book you have scrolled off the price, zooms about the pointer) by changing the price step per row (the Group select follows; Auto shows the step it is using); dragging the price column up zooms in and down zooms out, about the same point as the wheel (the price stays put on the middle row while the book is centred; Alt, or a book scrolled off the price, zooms about the pointer); a spin of the wheel makes at most four steps a second, one per event however many clicks it folds in, and a touchpad at most three (a gentle swipe is still a step), so one flick is a step or two and not the whole list; dragging the book moves it; double-click returns to Auto and the mark. Shift + wheel still scrolls Single mode sideways |
| Splitters, grips, the ⋯ menu | Resize the two columns and the panes under the map (a focused splitter moves with the arrow keys, 16 px a press, 64 with Shift; a double click gives a column back to the window, and the panes a splitter under the map parts their own height); drag a pane by its grip, or by its header where it holds no control, to move it: a side pane to either side of the map (a column that is not there yet shows a strip along the window's edge to drop on), a pane under the map between the others; the ⋯ menu (or a right click on a header) offers the same moves for a keyboard and a finger: to the other side, up, down, swap the two sides, reset the size; places and sizes persist |

Switched with Mirror in the order book's Cues panel (on by default; it left the Panels deck on 2026-11-12, where clicking it changed nothing until one hovered) |
| Hover | Shared time cursor across chart, depth, OI and Delta; price and liquidity readout on the chart |

Map, 5m ... 24h in its header choose the time span, the gear the ranking, row heights and re-ranking |
| Flow, Book (top bar), × on a pane, [ and ] | Show or hide the two side columns; a pane's × hides it and a column with nothing open leaves an edge tab that opens it again; [ and ] hide or show the left and the right column (matched by their place on the keyboard, so where a bracket needs AltGr the keys there do it: Ü on a German keyboard, whose right-column key is the zoom's +, so its edge tab does that one); a column that was closed with its key comes back with the panes it had open; on a phone Flow is a tab that fills the area. The venue chips show eleven venues and put the rest in a "+N" menu grouped by exchange; the bar along the bottom of a desktop page shows the connection, venues live, the price and its age, since when it records and where the data comes from, with the language and theme buttons |
| Hover (order-book cell or bar) | A box says that venue's size, its share of the level, its rank at the price and its distance from the mark; over the USD column or a plain bar it says the whole level with the venues behind it. The Mirror's box steps aside while the pointer is directly on one (its band stays) and returns anywhere else |
| Hover (order-book row, mouse) | The row's price is drawn across the map and its columns in its side's colour (its prices shaded where the grouping is wider than a few pixels there), with the price the book writes for it on the map's axis (at the axis's end, with an arrowhead, when the map does not show that price), and across the flow column's price strip when the window's prices reach it: the order book follows into the chart as the panes under the map follow the map's pointer |
| Hover (footprint row) | The row is boxed and a card gives its price span, what was sold and bought, the delta, which side was heavier and by how much, its share of the candle, whether it is the point of control, and the candle's own volume and delta (a trade bubble or a trapped-traders pop-up takes precedence) |
| Hover (bar-stats cell) | The cell is boxed and its candle's column and its row are tinted; a card says the statistic, the candle, the value, the candle before, where it ranks among the candles in view, whether it was flagged unusual, and what the statistic means |

The toolbar selects the market, timeframe (1m–1d), layer (a menu only once there is more than Liquidity to choose), heatmap source (aggregated or one venue), Spot / Perp / Both, the venues (the Venues button says how many are on and opens their switches and the feeds dialog), heatmap colour (Size ramp or two-hue Sides style, a legend showing the USD range with one Contrast slider, Auto, Smooth auto / off), the Profile / Depth / OI / Delta / LT / Volume toggles (the page opens with the map, the flow column and the order book only, the panes under the map one switch away; the two columns begin at the golden section of the window, 19 % of it each, and follow it until a column is dragged), Footprint (a lamp button with its own panel), Trades, Liquidations and Absorption (marks on the map), Volume profile, Key levels and VWAP (lines on the map), Highlights and Sound (what is unusual), each a split button: the button switches the feature on or off and its lamp says which, and the small key joined to its right (drawn sliders) opens the feature's settings, which stay as they were while the feature is switched; and the theme menu (hover a theme to preview it, click to keep it). On a desktop the toolbar is a console of framed decks (Market, Time, Heatmap, Panels, Chart, Alerts and the page's own), one row from 1600 px wide, scaled down to stay one row (to 85 %) on a smaller screen, and under that as few rows as fit (two, three on a narrow window), broken where the longest row is shortest so that no deck is left alone on a row (in rows Alerts stands beside Heatmap: Market, Time, Heatmap and Alerts over Panels, Chart and the page's own, which makes two rows even), each row reaching both edges with its decks grown in proportion and their controls spread across them, and nothing in it moves or changes size as data comes and goes. The flow column and the order book are 19.1 % of a wide window each, and narrower ones (to 260 and 350 px) on a window under 1600 px, so the map keeps its room on a laptop. Each kind of control looks like what it does: pane switches glow while their pane shows, the chart type glows while the price is drawn, features wear a lamp and a settings key, choices are segments or lists, and the buttons that only open something (Guide, Author, the screenshot) have neither. The ladder offers Compact (the default), Aggregated and Single modes, a grouping step and Levels / Cumulative / both; in Compact, Venue lines (off, top 3, 5 or 8; 5 by default) draws each of the largest venues' running total from the mark on a linear scale of their own (full width is the largest of them in view, with round-value gridlines), ranked by traded volume over the flow column's ranking window, and hovering a line shows it alone with its numbers (where a line crosses a bar it is a faint trace under the bar's labels, so the bars stay readable); and Pull/stack (off, 15 s, 1 min or 5 min): a column after LEVEL USD with how much resting liquidity each row gained (+, stacked) or lost (−, pulled) over that window, grey where the price traded in the window (a fill there looks exactly like a pull). It compares snapshots of every venue's book, counting a venue at a row only where its book reached the whole row both times; a venue that reconnects rebuilds its book and reads as a burst of both, and a coarse venue's banded levels spread their change over the rows they cover. The Liquidation levels, Stop loss and Take profit layers are not offered yet, and the Layer menu stays out of the bar and Settings until one is (2026-11-12; before, it listed them as upcoming): they need HyperTracker data, which a static page cannot hold a key for. Liquidations (positions the exchanges closed by force) are drawn as diamonds where the market was, from Binance (its latest each second only), Bybit, OKX and Deribit; Hyperliquid, Coinbase and spot markets publish none, and the panel says which of the venues switched on report them. Key levels draws the previous day's, week's and month's high, low and middle and each period's open (PDH, PDL, PDM, DO and the W and M ones), from one market's hourly exchange candles going back about two months; a previous level not yet traded through runs on, dotted, until price reaches it. VWAP draws the volume-weighted average price of the session (each day, week or month, with optional ±1σ/±2σ bands), rolling VWAPs over the last 1 to 365 days and up to four anchored VWAPs a coin, placed by clicking the map, from the chart market's exchange candles or from markets you choose (see *VWAP and anchored profiles*); the whale VWAP averages the recorded large market orders (from a size you choose), buys and sells apart.

**Liquidation levels** (**Liq levels** in the Chart deck, BTC only) draws the prices that would liquidate Hyperliquid's open BTC positions: HyperTracker's position snapshots (about one every 30 minutes), binned by the levels service (`HyperLiquidMap_Levels`, a separate Rust project) into $10 rows of long liquidations (in the falling-candle colour, below the price) and short liquidations (rising-candle colour, above it). They are a stripe right of the newest candle, so the heatmap keeps its own colours: the more a row holds the darker it is, with a crisp edge on the strongest, and a diamond marks a row where one position holds at least half. A snapshot describes the positions about 35 minutes before HyperTracker stamps it; from then on a level goes as Hyperliquid's price trades through it (its 1-minute candles, which can run a few basis points past the mark price liquidations use, and the chart's own price at once, so a move made before the page opened is taken too); snapshots older than three hours are not drawn. The page asks for a new snapshot when it can be there: the levels service asks HyperTracker 2,300 s after the held snapshot's creation (then every 3 minutes while the next is not ready), so the page asks from 37 minutes after it, each minute until it comes, every five minutes once 52 minutes have passed, and not at all while the page is out of sight; a snapshot seen to appear between two asks is placed without reading the page's clock and teaches the page how far its clock is off; until then a clock that is off makes the first few snapshots late, never missed (about four requests a snapshot instead of thirty; `src/app/liq-schedule.ts`). Their own column, between the map and the profile column, adds them up: what still stands in each row and, faint behind it, everything from the price out to that row; hovering it compares the longs below with the shorts as far above, as Mirror does for the book (a switch in the button's panel hides it). Pointing at a level gives what is at it, its distance, how much would be liquidated if price got there, the number of positions and the largest, and the isolated / cross split. The note under the legend says when the positions were taken (Powered by HyperTracker), and the Guide has a section on it. An indicator's values join the map's hover box only when the pointer is on what it drew.

A venue that never connects, keeps failing and fails a plain request while others work is shown as unavailable from the visitor's location: a dashed chip, a dismissible banner and a status in the Venues dialog say that a VPN set to another country may enable it.

The chips are the venues that have a book on the map. A venue that was chosen but has none gets a dashed chip of its own, so it never just disappears from the toolbar: a red-tinted one (warning mark) for a venue that is failing or, on a server, left off the map because its book is crossed (a feed fault: "book crossed by 123 bp"), a grey one (ellipsis) for one that has been connecting for more than 20 s. Hovering it says why. A server cannot push these changes, so the page asks it every 10 s.

**Help is built in.** Every control has a tooltip (`src/app/tip.ts`), and a **?** beside each pane explains it (`src/app/help.ts` holds the text both use). The **Tour** button lights the page a part at a time and says in a sentence what each is for (about a minute: `src/app/tour/`, see *The tour and the guide* below); the **Guide** button opens the long version, with a contents list in groups, a search box that forgives typos and moving pictures (`src/app/guide/`; an address like `#guide/mirror` opens it at a section). **Screenshot** (or `S`) freezes the page, lets you drag a region or click a pane (the top bar takes the whole page, every open pane and the flow column included), draw on it, pixelate or blur anything private, then copy or save a PNG (`src/app/screenshot/`; it draws the page itself, so nothing is asked of the browser). **Install** appears when the browser can install the page as an app, and **Author** says who made it.

On a young recording the heatmap is empty left of the dashed line that marks when the recording began: nothing is drawn where nothing was recorded, so every colour on the map is real.

## Phones and tablets

The page is arranged for the screen it is on. `src/app/device.ts` decides once, never from the user agent, and puts two attributes on `<html>` that `src/app/mobile.css` reads:

| Attribute | Values | Meaning |
| --- | --- | --- |
| `data-layout` | `phone`, `phone-landscape`, `desktop` | How the panes are arranged. A window up to 640 px wide, or a touch screen held upright up to 900 px (a tablet in portrait), is `phone`; a touch screen held sideways and up to 520 px tall is `phone-landscape`; everything else, a tablet held sideways included, is `desktop` |
| `data-bar` | `compact`, `full` | How the controls are arranged. `compact` on every phone arrangement and on any touch-first screen |

- **Phone (portrait):** a two-row top bar (the coin, status and Settings above; timeframes and recentre below; the market is chosen in Settings), the map, one pane at a time under it, and a tab bar (Tape, Flow, Map, Book, LT, Depth, OI, Delta, L/S, Stats: what has been traded, what rests in the book, then what is worked out from both; a tab exists while its switch is on in Settings, a phone starts with Tape, Flow, Map, Book and LT, and it opens on the Tape, the first tab; a mark under the open tab slides to the one chosen). The Tape and the Flow fill the area in place of the map, and so does the Book held upright. Tapping the open tab, or **Map**, gives the chart the whole screen. The handle between the map and the pane resizes it (remembered per tab and orientation; a double tap resets it). **Landscape:** one top row, the pane beside the map, the tabs as a rail along the edge. The panes are the same elements the desktop arranges as a column, so nothing is rebuilt when the tab changes (`src/app/dock.ts`), and a phone never writes the desktop's saved pane sizes.
- **Tape tab:** every trade since the page opened, as one continuous tape that never restarts and fetches nothing, so it opens at once. Each row is a price, sold at market on the left and bought on the right, its winning side shown more strongly the more it won; the order book rests either side, a rail at the right flashes where large orders arrive, and behind it runs the trail of every market order of the last 30 s, minute or 2 minutes, at the price and time it traded (filled dots buys, rings sells; whale-sized orders carry their exchange's mark). On glass the book's rows light up as liquidity stacks and dim as it is pulled, a shock running out along the bar or back in, and large orders send waves through the glass. The header says since when, from how many markets, and how long the page was hidden (a phone in the background gets no trades). Its choices (**Look**, **Trail**, **Glass**, **Rows**, **Pulses**) are in Settings.
- **Flow tab:** the flow column made for a phone, filling the area. The top is a chart: the price drawn over the taker flow of every exchange added together, spot in blue and perpetual in amber, with the dollars of the flow on one axis at the left (Settings, *Flow lines*, gives each kind its own range instead, as every row has, to read their shapes rather than their sizes) and the price on its own axis at the right with a tag at the newest price; a time axis runs along the foot and a dotted line marks where the flow began when that was after the window did. The spans are chips (5m, 15m, 1h, 4h, 24h; there is no map to follow here), and two fingers apart or together step to a shorter or longer one. A finger along the chart scrubs it (a dot on each line, a line through every row, and the line under the header reads the time, the price and each kind's running delta), a tap pins the moment (tap again to let it go), a press held moves the pin, a drag across the rows scrolls them and a lifted finger flings them, a double tap goes back to the top. Under the chart is a row for every exchange, the biggest first, each over its own range; the legend beside the chart gives each kind's net over the window it draws, so a figure agrees with the line beside it.
- **LT tab:** the Liquidity Tracker, with its half-life one tap away (chips for 10, 25, 50, 100 and 250 bp; the sheet's menu keeps the others) and the half of the screen under the map. It starts at 100 bp on every screen (a save that still held the old default, 10 bp, reads as 100 once).
- **Slim headers:** the header of a pane under the map is one row on a phone: its title, the choice that is made all the time (Range, Show, Mode and Group, the half-life), and a key at the end that opens the rest as a sheet. The Book held upright has no map above it and a crosshair key of its own that brings the book back to the price.
- **Settings** (the **⋯** button) is a bottom sheet of labelled rows holding every control that does not fit the bar: the pane switches with Trades, Liquidations and Absorption (split buttons, as on the desktop), the Tape's choices, the heatmap colours and contrast, the market and the venues, Highlights and Sound, the theme, Keep screen on, and Guide, Screenshot, Author and Install. Panels and menus become bottom sheets with a scrim; a dropdown opens the page's own menu (`src/app/touch-select.ts`) in the chosen theme instead of the system's list, and nothing makes an iPhone zoom in.
- **Fold the bar** (the small up-arrow at the bar's right end; on a desktop, on the bottom edge of the right-hand box): the top bar folds into a thin strip and the chart takes its room, as a browser's full screen hides its own bars; the strip's down-arrow brings it back. Each browser remembers its choice.
- **Gestures** (`src/app/touch.ts` recognises them from pointer positions; the recogniser is pure and tested): drag pans and carries on after the lift; pinch zooms time with the horizontal separation of the fingers and price with the vertical one, about the midpoint, so what is under each finger stays under it; dragging along an axis zooms it; tap pins the crosshair and its readout above the finger (tap again, or drag, to let go); holding then dragging scrubs it; double-tap recentres. The panes under the map share the time axis, so a drag or pinch there moves the map's time; the order book scrolls, pinches to zoom its grouping, pins Mirror on a tap and resets on a double tap. Holding any control shows its tooltip without pressing it.
- **Screenshot** works by finger (larger handles, buttons that wrap, a Share button where the browser has a share sheet), and records a GIF of the selected area as well as a picture: 1 to 15 s on a slider, never over 15 MB, saved as a file on a desktop (browsers cannot copy a GIF) and shared on a phone. **Keep screen on** uses the Screen Wake Lock API, because a sleeping screen stops the recording. **Install:** Chrome and Edge give a prompt; iPhone and iPad get an Add to Home Screen explanation.
- **Cost:** with the default eight venues the page received about 47 to 74 KB/s of exchange data (165 to 260 MB an hour); the three spot markets added on 2026-10-07 add about 16 % (measured side by side over three minutes: 12.8 KB/s on top of 78.6 KB/s of message text), so about 200 to 300 MB an hour with all eleven; on a 4x CPU slowdown the main thread uses about 13 % of a core with every frame on time (`Research_Findings.md`). The heatmap canvas is capped at 2 device pixels per CSS pixel on touch screens.
- **Testing:** the layouts are exercised in Chrome with a phone's size, touch events and device pixel ratio over CDP (`Emulation.setDeviceMetricsOverride` with `mobile: true`, `Input.dispatchTouchEvent`). That is Chrome, not Safari: the first real-device check is the published site over HTTPS (a LAN address over plain HTTP loses Web Locks and the clipboard).

## How it works

**Resilience.** `LiveFeedManager.start()` retires the old feeds before its metadata requests, so a failure in between used to leave a running server with no feed at all (`Research_Findings.md`). A failed start now schedules a recovery with the last configuration that finished, a watchdog restarts a start that hangs or a manager with no feed, and `/api/diagnostics` reports `feedManager`.

```
exchange feeds ─▶ LiveFeedManager ─▶ reducers (src/server/http.mts) ─▶ state
                                                                         │
                       ┌────────────────────────────────────────────────┤
                       ▼                                                ▼
        v2 recorder (src/server/v2)                          /api/v2/ws live levels
   minute columns on a shared price grid                      (binary, ~4 Hz) + ticks
   SQLite, 7-day window, footprint recorder                              │
                       │                                                 │
                       ▼                                                 ▼
          /api/v2/columns (binary) ─▶ raster worker + Rust/WASM ─▶ WebGL2 texture ─▶ chart
```

- **Valued levels** (`levels.mts`): every venue book is converted to USD (contract face value, quote conversion) with the price band each level represents. Grouped books (Hyperliquid's significant figures, Deribit's grouping) name a bid group by its lower edge and an ask group by its upper edge, Hyperliquid at one step per side (its best level's); the top bid and ask groups, which share an interval, are split at the venue's last trade.
- **Depth recorder** (`recorder.mts`): every 5 s each fresh book is spread onto a shared 1-2-5 price grid (about 0.02 % of price) and averaged per minute; stale books leave gaps rather than being carried forward. Columns are sparse (only non-empty bins), bid and ask separate, persisted to SQLite and kept for seven days.
- **Kernels** (`crates/hlm-kernels`): `raster_columns` turns recorded columns into a price-by-time grid (price-conserving, averaged over observed time only); `spread_levels` groups live levels for the profile, ladder and the live edge of the heatmap. The same spreading exists in TypeScript on the server and a test checks the two agree.
- **Candles and their history** (`hub.ts`, `price-history.ts`): the chart reads its last 500 candles of a timeframe and keeps them, by market and timeframe (sixteen series), so a switch shows the ones kept at once, framed, while a read brings them up to date (Karl, 2026-10-28: switching should be instant); after a series is shown the market's other timeframes are read one at a time, the nearest first, and again once they are three minutes old, and a switch to one with nothing kept clears the timeframe before rather than drawing its candles at the new spacing. A returning visitor's series is asked for as the page starts, the page does not wait for a first live price when it knows its market, and the candles are framed without waiting for the open interest's history. Where the view reaches past those candles (before them, in a hole, or while they are on their way) the exchange's own history is read straight from the exchange (Binance first; `shared/price-history.ts`) at the chart's timeframe wherever one read of 2,000 bars holds the view, and drawn as candles of the chart's type, with its volume in the Volume bars, caught by the magnet and said under the pointer; a longer view draws it coarser, as a line (in weeks once its days are more than one read holds, about four and a half to five years of view), and another market's history as a dashed line. Scripts and the VWAP run on the chart's own candles only.
- **Rendering**: the worker rasterises a window 20 % larger than the view; the shader samples it with a view-relative transform, so pan and zoom stay smooth on the old texture until the next raster arrives.

## Heatmap colour and the Liquidity Tracker

- **Size style** (default): one sequential colour ramp encodes size on a log scale; bid or ask is implied by position relative to the mark. Cells below the window stay background. **Sides style** uses two hues by side on a linear window.
- **Contrast** is one slider (-100 to 100, 50 = the baseline): it slides the colour window along the size axis (right shows thinner liquidity, left keeps only the biggest walls, and the far left tones even those down, which is what many venues added together need, because their walls are huge; double-click resets). The window moves by up to three quarters of its own width to the right and 2.25 widths to the left (`src/app/heatmap/window.ts`). The window comes from the 15th and 96th percentiles of the non-empty cells; it is taken again on recentering, a market or venue change and a 2x zoom (with Auto off too: a cell holds every price of its row, so cell sizes follow the zoom, and a window kept from another view would saturate everything or nothing), and follows the cells for 15 s after that while the view's history loads (`nextBaseline`). Then Auto blends it toward the cells every 10 s, so colours do not drift while you pan; Auto off holds it.
- **LT row** (optional, toolbar toggle): LT-Bid and LT-Ask are the USD size on each side of the aggregated enabled venues, weighted by 2^(-d / half-life) with d the distance in basis points from that side's touch (basis points rather than ticks so venues with different tick sizes agree). Options: half-life, min / max bin size, per-level average, lines or imbalance view. It is computed in the raster worker from the recorded minute columns plus the live column, so changing a setting recomputes the whole visible history at once (`src/app/lt.ts`, unit-tested). Where the page's server answers it, the pane asks the server for the tracker alone over the live socket (a few hundred kilobytes where the map's columns for the same view are tens of megabytes), newest day first, so a week is there at once and does not wait for the map's own load; a size filter, an older server and the browser engine read the recorded columns as before. In the imbalance view the axis follows the largest imbalance in view (2, 5, 10, 20, 50 or 100 %, named on the axis), so a book a few percent out of balance fills the pane.

## VWAP and anchored profiles

The **VWAP** button (Chart deck) draws the average price the market traded at, weighted by volume. Its panel has three kinds, which can be on together:

- **Session VWAP** starts again at each day, week or month (or at a time of day you choose), with optional ±1σ / ±2σ bands: where this session's buyers and sellers have done business on average.
- **Rolling VWAP** keeps the last 1, 7, 30, 90, 180 or 365 days up to each moment (`RVWAP 30D`): as time moves on the oldest trades drop out, so it never restarts, and it is the same line on every timeframe and zoom.
- **Anchored VWAP** keeps everything from a moment you choose, up to six a coin and as far as ten years back. Choose the moment three ways: tick a box in the grid of periods (a column for the day, week, month, quarter and year; a row for its start, its high and low so far, and the previous one's high and low), and the line follows that rule, *Week high so far* moving to each new high as it prints; type a date and an optional time on the chart's clock, said back before you add it; or *Click a candle* (a drag still pans, Esc cancels, the arrow keys and Enter work too, a tap on a touch screen shows where and *Place here* puts it there). On the chart a live anchor is named by the traders' code (AVWAP PWH, AVWAP YO), a fixed one by its date. Each anchor's row shows where it starts now, hides it, freezes a live one at its candle or moves it to a date or another candle (*Edit*), and removes it, all with *Undo*.
- **Colours.** The session line, each rolling window and each anchor have a swatch (the system's colour picker; the line changes as you drag), the Volume profile its buys, sells and point of control with the value area. Each starts in the theme's colours (greens for rolling windows, violets for anchors, each with a dash of its own); *Reset colours* takes them back, and a colour hard to see on the theme you switch to is said.

**Candles from** says whose candles they add up. *The chart market* (the default) is the market on the chart, or the most traded one that lists the coin where the chart's history cannot be read. *Chosen markets* adds up to six markets bar by bar, each exchange's spot and perpetual ticked apart (Binance, Bybit, OKX and Bitget have both, Coinbase spot, Hyperliquid and Deribit perpetuals); the boxes start from the market the lines read now. The bands keep the spread between the markets, not only their average. Every market more is more to read, a line waits until each of them reaches its start, and the panel names a market that could not be read, has not been read for minutes, or whose history does not reach far enough back (with the date). Prices quoted in USD, USDT and USDC are added one to one. Session lines reach about two months back, rolling ones a year and anchored ones ten years; Hyperliquid serves only its newest 5,000 candles of each interval and Bitget about a month of minutes, so a long window on those can be too long for their history.

**Anchored profiles.** The Volume profile panel's *Columns cover* is *What is on the chart* (the default) or *From an anchor*, chosen as the VWAP's are: a round button in the grid of periods (it follows that period), a date, or *Click a candle* (one a coin). Every column beside the map (traded volume, liquidations, absorption, open interest) then adds up from that candle to now, the point-of-control and value-area lines start there, and a dashed line on the chart marks it. The columns are worked out again every 5, 15 (the default) or 60 minutes rather than with every trade, or at once with *Update now*, always up to the last whole five minutes; the panel says what they hold and when it was worked out. Traded volume reaches back two years, as an estimate from candles (≈): five-minute ones for the last 21 weeks and the zone's hourly ones before (so an older anchor starts on the hour); an anchor still being found or out of reach leaves the columns empty and their header says why; liquidations, absorption and open interest only as far back as their recording (the volume column's header says where its numbers begin). The bands along the top stay with the chart.

## TPO (Market Profile)

The **TPO** button (Chart deck, `O`) draws Time Price Opportunity profiles on the map: each day, week or session (the Volume profile's zone and sessions) is cut into blocks, half an hour each by default (four hours for a week), lettered A to Z and then a to z; a block stands at every row its half hour traded at, and each window's rows are stacked from its start, under the candles, over a backing that mutes the heat map (`src/app/tpo/`, `tests/tpo.test.mts`, whose fixture day reproduces the calls and hollow rows of study TPO-1, the measurement the rules below come from).

- **Look.** Blocks are coloured by the time of their half hour, early warm to late cool (or by how full their row is), with letters inside once a row is about 11 px tall. Zoomed out, where a block would be under about 1.6 px, the profile is drawn compact: each row one bar as long as its blocks, in the colour of when the market was at that price (the mean time of its blocks, or how full the row is), rows finer than a pixel gathered into one bar a pixel row, each block's own rows counted (as the point of control counts them; what one chosen market alone reached is left out); laid out in time, one bar a block (Karl, 2026-11-11: the 1-px outline drawn there before vanished on the heat map, so the TPO seemed to be drawn only where the page had recorded). The point of control's row is a light stripe, rows outside the value area (70 % of the blocks by default) are dimmer, the initial balance (the blocks of the first hour; the first block where blocks are an hour or longer) is an amber bracket at the left with IBH and IBL, small arrows mark the window's first price and its last, single prints get an amber bar, and a few numbers under each profile give its range, initial balance, blocks above and below the point of control and volume. The longest row is at most three fifths of its window on the chart, at least 8 px but never wider than the window itself (zoomed out to months, a day's profile fills its few pixels instead of lying over the next days). Narrower than 3 px, or in a window under 6 px, a profile is a strip: its range dim, its value area in full and its point of control as the light stripe, in the colour of when the market was there, a few rectangles a day. Compact bars are filled one path per colour, over a casing: the page's background colour at 0.85, a pixel larger than each bar all round, filled once under every compact profile before any of them is drawn, so a strip keeps its edges over a hot heat map and a neighbour's casing never covers it (Karl, 2026-11-12: at a two-month zoom the strips blended into the map's blues and oranges).
- **How sure a call is.** A tail (two or more rows of one block at an extreme) or a poor high or low (a top or bottom row of two or more blocks) depends on where the row edges fall: in study TPO-1, moving every row by part of a row changed Binance's own BTC call on 47 % of days at $50 rows. Each call is therefore worked out on four row grids, the rows moved by none, a quarter, a half and three quarters of a row, and says how many agree ("Poor high · 2/4", amber when two or fewer). Auto rows are the 1-2-5 price nearest a typical day's range over 90 (the coin's last 14 complete days from its daily candles, so the size does not move as history loads; 24 % of BTC days at its $20 Auto rows), or a price chosen for the coin.
- **The other venues.** A block is drawn as an outline where the chart market's wick went at least a row and 3 bp past the point most of the market's volume reached in that half hour, with its range widened there: the other venues switched on inside Spot / Perp are read at the same block size, each moved by its median gap to the chart market over the day before (USDT spot sits about 4.5 bp over the USDT perpetuals, Coinbase about 8 bp under Binance's perpetual), and a range that only moved is the gap changing, not a wick. Rare on the large perpetuals (about 1 % of BTC half hours), more on Coinbase (about 5 %). The block's box says how far it went and who traded there. The other venues' candles are read two months back at most (every venue switched on for a year would be hundreds of requests), and only while a window drawn ends within them: older blocks are drawn without hollow marks, as the panel says.
- **Laid out in time.** `U` (or Laid out in time in the panel, or the block menu) moves every block to its own column at its half hour, behind its own candles, and folds them back, animated. Pointing at a block gives its half hour, its row and every half hour in that row, the point of control, value area and initial balance, and lights its half hour across the map.
- **Split, merge, composite.** Right-click a block to split its window at that half hour, merge the window with the one before or after, or undo them (kept per coin, kind of window and block length, outside layouts: a day's split never cuts a week; a merge joins only windows that touch, so overlapping sessions cannot be merged). On a touch screen a tap pins the block and its box ends with *Tap this box for the TPO menu*: a tap on the box (or a second tap on it soon after, which the gestures read as a double tap) opens the same menu, as a bottom sheet on a phone, for the block under the pin if it is still the one the box names; a choice puts the pin away, and the click the browser makes of the tap is dropped so it cannot choose a row or close the sheet. A Range selected on the map (`X`) draws the composite of every block in it over the windows it crosses.
- **Lines.** While the TPO shows, the Volume profile's lines of the same kind of window (point of control, value area, the previous period carried, untouched points of control, their tags) are drawn at the TPO's levels and named "TPO"; with those lines off, the TPO draws its own point of control across its window. With the Volume profile's profiles on for the same windows, the volume profile is drawn as an outline over the TPO's blocks, as wide as its longest row.
- **Windows and reach.** Every window in view by default (How many: All in view, at most 400 of each kind, as many days as the candles are kept, and 800 in all, the newest, and the one before the left edge, which a merge may join; sliced from the kind's calendar over the whole reach, laid out once a day), or the latest 1 to 20 up to the chart's right edge; a count of 5 saved before settings revision 2 (the old default) reads as All in view. Candles are kept about thirteen months back (`TPO_REACH_MS`, 400 days, and never more than 40,000 of one market: a session starting off the quarter hour is read from minutes and reaches four weeks, as the panel then says; daily candles for Auto rows 475), read from the exchanges as the chart scrolls back, never from the recording: a day a year ago draws as today's does. Auto rows are read from the days before the chart's right edge once it is more than four weeks back (on a four-week grid, so panning moves them rarely), and keep the last size known while those days load.
- **Data.** The chart market's candles (the key levels' choice of market), at the block size where every window starts on it, else the largest size that divides both (over the whole reach, both daylight-saving offsets); the block under way follows the chart's own candles and price; a replay reads only candles over by its moment. Each window is worked out once its candles reach it, from its own candles (and the day before, where gaps are read), and again only when they change: a pan or a refresh of the newest candles leaves every other window as it is (the hollow marks likewise, per window, and again when more of its blocks can be judged). A frame works out about 12 ms of profiles (two at least; the day's calendar and the candles' signatures come before), the newest first; the rest follow on the next frames, each drawn as it was until then (a first look at a year, or a change of rows, is hundreds of windows). While a market a window waits for is on its way again (a retry, a walk further back) the window keeps the profile it had from the same markets and rows; a market that could not be read at all stays down until candles come, so the windows neither wait for it nor blink with each retry. A chart market whose history begins after a window (Hyperliquid's newest 5,000 candles) draws no TPO before it, as the panel says.
- **Candles from chosen markets.** With Candles from set to Chosen markets (the panel's picker, up to six, in the VWAP's form, `binance/perp` or `coinbase/spot`, so a layout made on BTC means the same exchanges on ETH), each market is moved by its trailing median gap to the chart market (where the chart market has no candles in a window, to the first chosen market that has), a block spans the volume-weighted median of their highs and of their lows (one market's lone wick adds no row; the largest market decides where it holds most of the volume), its volume is all of theirs, and its open and close are the chart market's where it is ticked, else the largest's (`mergeBlocks`). With hollow marks on and three markets or more, where one market's wick went at least a row and 3 bp past that, its range widened there, the block reaches on to it: those rows are drawn hollow and never counted (the point of control, value area, tails and poor extremes are the blocks' own), and the box names the market and how far it went. A window waits until every chosen market, and the chart market they are moved into, reaches it or never will; a market whose history begins after the oldest window drawn (Hyperliquid serves its newest 5,000 candles) is named in the panel. No other venue is read for hollow marks in this mode.

## Footprint

The Footprint panel's Markets row chooses whose market orders the footprint and the bar statistics count: Aggregated (the default), the markets of the flow column's ALL VENUES lines (every venue switched on, inside the Spot / Perp filter, one spot and one perpetual market each, as the Delta pane adds them) added together on the chart market's candles, or the chart market's alone. Each market's trades stay at its own prices, so the rows are sharpest with the filter on Perp (USD spot markets can sit 10 bp or more from the USDT perpetuals). Open interest in the bar statistics is still the OI pane's one market.

The Footprint panel sets what a row prints (sold × bought, the delta, the total, or nothing) and outlines diagonal imbalances: a row's sells at least the ratio (3 by default) times the buys one row up, or its buys against the sells one row down, outlined in their side's colour, with the ratio in the row's popup. The ratio, the minimum size, whether a row beside an empty one counts, and the stacked rows are shared with the bar statistics, so the strip counts what the cells show; they are read on the rows shown, so zooming changes which rows stand out.

With the Footprint on (the first switch of its panel) and the chart zoomed in, each candle slides to the left of its slot as a solid candle and the rows of executed volume appear to its right (design after the footprint screenshots in `example_images/`). A row prints sell volume (market sells hitting bids) then buy volume (buys lifting asks) in compact form (13.4M, 407.0k). A bar anchored at the column's left edge appears only where one side is at least 1.15 times the other; it is red for sellers and green for buyers and sized by the larger side against the largest in view. With Aggregated, the bar is split into each venue's part of that side, in the same order on every row and shaded in turn, with the venue's mark where a piece is wide enough (the row's popup names every venue, with what it sold and bought). The heatmap dims behind it and the footprint fades in and out with zoom (thresholds in `FOOTPRINT_POLICY`). Below the chart the Bar stats table (its own **Stats** switch among the panels) prints per-candle statistics aligned to the candle slots (see below).

### Rejected aggressive buying and selling

On a closed candle whose wick holds more net aggressive buying (or selling) than any equally tall stretch of the rest of the candle, and that then closed at least one ATR beyond the aggressors' estimated average price, the wick's imbalanced cells are outlined in amber and, for twelve candles, slowly pulse (still, not pulsing, with reduced motion or once price closes back through that price). Hovering them says what was bought and sold in the wick (net, share of the wick's volume, share of the candle's), and what is not known. It describes flow that price then rejected; it does not say who holds what, and the pattern has not been tested as a predictor. It judges only settled candles whose footprint holds the candle's whole volume (checked against the exchange's own figure, so a quiet minute is not a gap and a partly seen candle is), each on its own row step from the volatility before it, decides each candle once (final a minute after it settles), and says in the chart's header, for the candle under the pointer, whether it was checked, had nothing, lacked data or lacks history to compare with. It needs the candles and footprint of the same market. `Research_Findings.md` has the rule, the firing rates behind its defaults, the ways it can mislead and what a proper study would take.

### Bar stats

A feature of its own: the **Stats** chip among the panels shows or hides it (a dock tab on a phone), whether the footprint shows or not; a save or layout from before the switch keeps the table where the footprint was on. It loads the same bars as the footprint (one load while either shows) and counts the markets the footprint counts, a choice offered in both panels. Its footprint rows (poc, imbalances) are read on rows of the size the footprint would draw at this zoom, which its header names (`rows of $64`): with the footprint off, zooming the price axis changes them too. A click on a candle pins a card of every statistic for it (a click on another candle moves it, Esc lets it go); Shift+click pins up to five at once to read them side by side.

The table shows volume, delta and cumulative delta by default. The **Stats** button in its header opens a panel to choose any of the following, reorder them by dragging a row by its dots (or focus the dots and press the up / down arrow keys), hide them with ×, or apply a preset (Default, Order flow, All, None); the table grows one row per statistic, and choice, order and options persist in the browser.

| Group | Statistics |
| --- | --- |
| Volume | vol, delta, cvd, delta %, buy vol, sell vol, candle delta (Binance's own taker buys minus the rest, in USD at the typical price; before the recording too), rec % (how much of the candle the recording holds), venues agree % (the share of the volume on markets whose own delta had the sign of the total; several markets added together) |
| Footprint rows | max buy, max sell, poc (point of control, the row with most volume), poc move (from the candle before), poc in range (0 % at the low, 100 % at the high), imb # (diagonal imbalances), stacked (runs of adjacent imbalanced rows) |
| Trades | trades, buys, sells, avg trade, avg buy and avg sell (the dollars of the market buys, or sells, over their number), fills and avg fill (the chart market's own candle: Binance's trades, every fill counting, and its quote volume over them; before the recording too), size skew (average market buy against average market sell), whale % (share of order volume from the whale size up), delta retail, delta whales, cvd retail, cvd whales |
| Candle, open interest and liquidations | range (high − low), close in range, vol / bp (the candle's volume per basis point of its range: effort against result), delta vs candle (▲ a candle that fell on net market buying, ▼ one that rose on net market selling, delta at least 5 % of volume), OI change, oi × delta (+/− OI rose or fell, ▲/▼ net buying or selling: a reading, not proof; blank where only spot markets' executions are counted, as under the Spot filter), liq and liq Δ (liquidations reported on the markets counted, their sum and shorts less longs, asked a UTC day at a time so ≈ shows only where one day held more than the 5,000 an answer carries; a candle the record does not reach, kept a week and only since the recording started, stays empty) |

The columns are the chart's candles: rows read from candles and open interest fill the candles before the recording too, and rows read from executions are drawn faint where the recording holds only part of a candle (rec % says how much). Marks (delta vs candle, oi × delta, rec %) are tinted by side and empty where there is nothing to mark. The **View** column right of the table, under the price axis, gives each row over the candles in view (a sum, a running sum's newest value, or a figure worked out from those candles added together; its popup says which). **Export CSV** saves the candles in view, one line each, a column per statistic shown (marks as text, size skew as the buy/sell ratio, a UTF-8 byte-order mark for spreadsheets). **Cells** are shaded by size among the candles in view (Filled), by how far each stands above its own recent candles on the Highlights' baseline, 0 to 3σ (Unusual), drawn as one line per row (Line), or left as coloured text. **Group rows by kind** gathers the rows under a header per kind; a click on a header folds its rows away (the pane is sized again only when the rows, the grouping or the folding change). A click on a candle **pins** it: a card lists every statistic for it until it is clicked again or Esc is pressed. **CVD from** each day's start makes cvd, cvd retail and cvd whales start again at every day in the chart's time zone (the footprint's bars are then loaded from the start of the day the left edge falls in). `src/app/panes/bar-stats.ts` defines every statistic (`compute`, `view`, `source`); the Astra and advisor consultation of 2026-10-20 chose the new ones.

Options: cell style (filled and shaded by magnitude on a log scale between the visible 2nd and 99th percentile, or text only coloured by sign), OI change in base coin or USD, imbalance ratio (default 3: a level counts when it is at least that many times the opposite volume one row away), minimum imbalance USD, stacked row count, and the retail/whale limits by trade-size bucket (0, 25k, 50k, 100k, 250k, 500k, 1M, 5M USD; retail up to bucket 2 and whales from bucket 5 by default).

cvd sums the bars loaded for the view. Trade counts and size buckets are recorded by the server from the moment this feature was installed, so earlier bars show `–` for the Trades group; like all executions they are recorded only while the server runs.

## Delta and CVD candles

The Delta pane (a toggle in the toolbar, off by default; a dock tab on a phone) shows, for each candle of the chart's timeframe, what was bought at market minus what was sold, in dollars, over the same markets as the flow column's ALL VENUES lines (the exchanges switched on, inside Spot / Perp). **Delta bars** draw each candle's delta on its own; **CVD candles** draw the cumulative delta as candles, adding up from the chart's left edge, or starting again each day or each week in the Volume profile's zone, with a dotted line where it starts again. A CVD candle's open and close are exact; its high and low are the running sum sampled sixteen times through the candle, because the extremes of a sum over several exchanges are not kept, so a wick can be a little short. The numbers come from the flow the page holds (a day a second at a time, older minutes where the server keeps them): candles before that have none, and after a stretch with nothing recorded (ten minutes or more without a trade on any of the markets is taken as that) the CVD carries on from where it stopped, past a dotted line and in a run of its own: what traded in the stretch is not counted, and divergences do not reach across it (it used to start again at 0, so the part after a gap sat at a level of its own that moved against the rest with the left edge). The candle under way keeps the highest and lowest it was seen at, so its wick does not flicker as its samples move. With **Divergences** on (the default), two swing highs in a row where the price made the higher high and the CVD the lower one are joined in the sell colour above the highs, and two swing lows where the price made the lower low and the CVD the higher one in the buy colour below the lows, on the CVD candles and on the map (the newest six in view). A swing must stand beyond 3 closed candles each side (2, 5 or 8 in the header), so a divergence appears that many candles after its newer swing and never moves; swings across a restart of the CVD are not compared, and none are drawn while the chart borrows another market's candles. They show where buying or selling faded against the price; they have not been tested as a signal. Hover a candle for its delta and the CVD it closed at (`src/app/delta/`, `src/app/panes/delta-pane.ts`, `tests/delta.test.mts`).

**NL/NS** (the third choice of Show) estimates who opened and closed positions: each candle's change of open interest of the OI pane's market (with venues added together, of each venue, then summed), given to the side that traded at market there (that market's taker delta; the way its price went where its flow is not recorded, which the header says). Up with buyers: new longs; up with sellers: new shorts; down with sellers: longs closed; down with buyers: shorts closed. Each candle's bar holds all four parts, in coins: above the line what buyers did (new longs solid, next to the line, then shorts closed, lighter), below it what sellers did (new shorts solid, then longs closed, lighter), and the few much larger than all the others are cut at the edge with a gap across them, so the rest keep their proportions (the popup gives the numbers); what went to no side is in the popup only. The readout gives the running net since the start (the net positioning of the side that traded at market), restarting where the CVD does and carrying on past a gap as it does. Every position has a long and a short holder, so it is an estimate, for that one market; tested against the moves that followed, it is context, not a signal. A market's change is measured between its own readings and given to its takers over the whole stretch since the reading before (an hourly reading is marked coarse in the popup); each venue is classified before they are added, so new longs on one venue and new shorts on another read "Both ways" with the four parts listed, not "no change"; Deribit's open interest, counted in dollars, is put in coins at one price (the newest close), so a price move alone opens and closes nothing. The header's **As** select (with NL/NS shown) switches between Four parts and Longs and shorts: the running sums of the longs and of the shorts as two lines.

**NL/NS minute by minute.** Where a venue's minute readings and its flow each minute cover a candle (the last day, `OI_FINE_MS`, on the venues read every minute or every five; the store's `oiFine`, read while something that uses NL/NS is shown), the candle's parts are those of its minute pieces added up: each reading's change given to the takers since the reading before. Inside a long candle, longs opened at market early on and shorts closed later are then both seen, where the candle's one delta names one side. Measured against every Hyperliquid trade's own change of open interest (Research OIF-1, 2026-11-06: BTC and ETH, 30 holdout days each), minute pieces named the side that added more of the new contracts for 94-95 % of the rise per 15-minute candle against 90-91 % from the candle's delta, and per hour 93-96 % against 87-88 % (significant on ETH, not on BTC's 30 days); a candle the minute readings do not cover keeps the reading per candle, and the popup says which. One model (`src/app/delta/nlns-source.ts`) serves the Delta pane, the OI pane and the Funding pane.

**Chosen markets.** The footprint's Count (in its panel) and the OI pane's Venues can also be Chosen markets: a list of exchanges and kinds (Binance perpetual, Coinbase spot) ticked whatever the venue chips and the Spot / Perp filter say, the footprint's and the open interest's apart (spot markets have no open interest). NL/NS and the Long/Short pane count the OI list, and the Delta header opens it while it shows NL/NS. A choice is an exchange, not a market, so a layout made on BTC picks ETH's markets on ETH; one the coin is not listed on counts nothing, and an empty list counts nothing.

**Long/Short** (L/S in the pane toggles, off by default) shows the share of each exchange's accounts that is net long, as the exchange publishes it, one line per exchange with its mark where the line ends: Binance, OKX, Bitget and Gate (all accounts by default; their top traders by accounts or by positions with Series in the header; OKX's top traders about 30 days back, Gate's "large holders" 90 days and more, Bitget's newest 30 readings only, its top traders "active" in its English documentation and "large traders" (大户) in its Chinese), and Bybit, for the OI pane's markets, and Gate's USDT perpetual when the OI pane counts every market (Gate publishes no open interest the page reads; a coin it does not list reads as publishing none). These count accounts, not coins (in coins the two sides are always equal), so 1.25 is 1.25 long accounts for each short one; the exchanges count different people, so the lines are never added together. OKX sends no CORS header, so the website says a web page cannot read it; HTX, Kraken Futures and Bitfinex publish long/short data the same way and are left out, and Hyperliquid publishes none (surveyed 2026-10-21). Bitget allows one request a second, so the cache spaces its requests. The readings are read from the exchanges when the pane is shown and kept in memory and on disk apart from the history (the server's own `long-short.sqlite`, a page's own IndexedDB database), so after a restart or a reload only the hours since are read from the exchanges; the pane draws what is kept at once and the rest as it comes, five-minute periods at the finest; a view shorter than about a month keeps its window under 30 days, so they stay as fine as the candles (from 30 days the cache reads daily readings), and the series not shown are read quietly once a window so switching draws at once.

**Where each profile is drawn** (the Volume profile panel's *Where each measure is drawn*, `src/app/traded/profiles.ts`, `arrange.ts`, `placement-panel.ts`, `tests/profile-placement.test.mts`). A grid with a row for each measure (traded volume, the change in open interest, absorption, liquidations) and a column for each place: **Right** of the map (beside the book profile, as before), **Left** of it (between the flow column and the map, mirrored: the bars grow from the map's edge outward and the price tags stand at the outer edge, so both sides face the chart; same header, value area, hover box and Range drag), and **Top** (bands along the top, by time). Any cell can be on, so one measure can be drawn in several places; a small picture of the chart beside the grid shows which edges hold which profiles, stacked as they will be. Each switch is a profile instance (`traded.placements`: an id given once, the measure, the place, its order outward from the plot, and fields for a window, a size and a look of its own that version 1 keeps at the chart, the page's size and the shared look); older saves and layouts read their columns as columns on the right and their profile along the top as it was. The map keeps at least half the width counting the columns on both sides (the nearest the map on each side stay, the outermost wait), and up to three bands stack (about 96 px alone, 70 at two, 56 at three, a quarter of the plot at most); what has no room stays switched on and is said in the panel and by a small amber tag on the map, which opens the panel. Phones keep one band and no columns. Every measure is one registration in `src/app/measures/defs/` (`measures/registry.ts` lists them; `measures/measure.ts` says what one holds: names, side words, header, notes, and its by-price and by-time providers), so a measure added there is a row of the grid and can go anywhere. Questions are keyed by measure and projection, never by place: a measure drawn on both sides reads one answer by price, and moving it from one edge to another asks nothing new. The lines across the chart are traded volume's wherever it is drawn by price, else the first measure drawn by price, and the panel names that measure.

**Volume profile along the top** (part of the Volume profile, a *Top* cell of its places, off by default since 2026-10-28 with traded volume ready in its cell (it repeats the Volume bars along the bottom and covers the top of the map; a save from before keeps it as it was), shown while the Volume profile is on; a click on a band's header opens the places) is the profile column turned onto the time axis: a band under the legend and the map's corner buttons, the column's width tall (less on a short chart), on the column's panel background. It adds up the same measure over the same stretch as the columns (what is on the chart, its newest eight days at most), on the same markets and at the same thresholds, in buckets of one round length (1 s, 2 s, 5 s, 10 s, 15 s, 30 s, 1 min up to a day) as near to the column's rows (about 3 px) as the zoom allows and never under 2 px. Each bucket hangs down from the band's top edge as a row grows right from the column's edge: the first side in the bid colour, then the second in the ask colour, its length the bucket's total against the busiest; with **Delta** bars the whole bucket faintly and the difference over it on the same scale. The busiest bucket is the point of control (a solid line) and the value area the run of buckets around it holding the column's share (shaded, its start and end dashed), each tagged with its time; the header gives the measure's total, the busiest bucket and the Δ line, and says in amber when the record is cut. Pointing at a bucket gives the column's row box with its time span for its prices. **Traded volume** is bought (gross + delta) / 2 and sold (gross − delta) / 2 per bucket from the flow the page holds, exact to the second for the last day and to the minute before it (buckets are then a minute at least, and the caption says the data, not the zoom, set that); ten minutes or more with nothing traded on any market is not recorded, as in the Delta pane. **OI change** reads each perpetual's open interest by the minute, whatever the chart's timeframe, takes the changes between readings by the column's rule (no gap of more than an hour, wholly inside the window: `oiIntervals` in `src/shared/oi-profile.ts`), spreads each over the minutes it came about in by the market's traded volume and values each part at the price that traded then, so the chart's candles never price it; the increases and the decreases are added apart, never netted and never called buying, and a change that cannot be placed (across a gap, with nothing traded under it, past the window) is said in the header as the column says it (a minute at least; the caption says how often it is read). **Liquidations** are every one the record keeps over the window, as the column asks for them (the largest 5,000 when more, said in the header). **Absorption** is the marks' groups at the marks' thresholds, loaded for the window while the band shows them, the marks on or off; where a busy minute kept only its largest groups and left out a mark (the minutes' floors, judged by the column's rule), the header says some minutes are in part. A bucket with no data has no bar but a faint dotted line along the top edge, and its box says why: it is never a zero (`src/app/measures/`, `tests/measures.test.mts`).

**Emphasise the bigger side** (on by default, under Bars in the Volume profile panel, split bars only) draws the stronger side of each row of the columns, of the profiles on the chart and of each bucket of the band a little stronger and the weaker one fainter, on a smooth curve of how one-sided it is: q = (b − s) / (b + s + τ), with τ the larger of $25k (scaled to the coin) and 5 % of the busiest row of the whole answer, so a thin row stays even; full from q = 0.8. The weaker side goes from alpha 0.85 to 0.35, never gone; the stronger keeps 0.85 and moves 0.08 in OKLCH lightness toward the text colour, inside sRGB (`src/app/traded/emphasis.ts`, `tests/emphasis.test.mts`). It says what happened, not what comes next.

**The previous period's levels** (Volume profile panel, Line contents: *Carry the previous period's levels*, on by default) draw the point of control, VAH and VAL of the previous day, week, month or session across the whole of the one under way, long-dashed and fainter, named "Previous Oct 24 POC 80,730" (≈ from candles), whether or not price has traded through them; each kind whose lines are on does it, each session on its own. It shows only when that previous period can be worked out by the lines' own rules: from the recording a server holds yesterday and the days before it but never a previous week, a page that reads the exchanges itself holds none (the panel says so); candles reach further, months always. The older a day, week, month or session is, the fainter its lines and profile (the two newest of each kind in full). `src/app/traded/carry.ts`, `tests/traded-carry.test.mts`.

**Volume bars** (toggle Volume, on by default) run along the bottom of the chart, one a candle, split into what was bought and sold at market (`src/app/measures/volume-strip.ts`). Where the recording reaches, a bar is what every venue switched on inside the Spot / Perp filter traded; before it, and under the exchange's history candles before the chart's own, the chart market's own candle, outlined: Binance's quote volume and taker-buy quote volume as reported, with its trades; another exchange's volume at its typical price, marked ≈. Hovering a bar gives its volume, its sides and delta with their shares and, for a recorded bar, its market orders, read for that candle once the pointer rests on it (`src/app/measures/strip-orders.ts`): their number on each side, the average buy, sell and overall order (the orders' own dollars over their count, each order at the minute its first fill came), the share and delta of whale orders from the Bar stats' whale size, and the largest venues. A Binance candle adds its trades and the average fill, a fill being one match, not an order. The strip draws no value area or point of control (2026-10-21: the volume was to keep its design with more data, not become a profile).

**Funding** (in the pane toggles, off by default) shows one venue's funding for the chart's coin: Hyperliquid, Binance, Bybit, OKX, Bitget or Deribit (the Venue select; Hyperliquid by default), read by the page itself (every one answers a browser) and kept in memory. Every rate is per eight hours (Hyperliquid settles each hour, ×8; Deribit's records say what each hour paid, ×8; a venue settling every four hours ×2), so the base rate (0.01 %, dashed) and the band around it where the premium moves while funding stays put (±0.05 %, shaded) are the same on every venue that has them (Deribit's funding is continuous with no base rate: zero while the premium stays within ±0.025 %, its documented default, and the premium less that margin outside it; no band is drawn for it, since a perpetual can have its own margin). Settled funding is drawn as steps, each over the interval it paid for, the one accruing now dashed; the premium is a line where the venue publishes its history (Hyperliquid each hour with its funding, Binance's and Bybit's premium index per candle); OKX, Bitget and Deribit show their funding only. On Hyperliquid, under each hour, the share of new positions buyers opened at market (NL/NS minute by minute, `NlnsSource.hourly`, the last day in a page and the last week on a server, from a dotted mark with that span written beside it, with its perpetual among the OI pane's markets): Research OIF-1 measured Hyperliquid's funding moving with that share hour by hour within a day (Spearman +0.21 / +0.23 on ETH / BTC over 30 days each, and +0.59 / +0.69 across days), its premium more so on BTC (alike on ETH); on other venues the link was not measured, and nothing here was tested as a signal (`src/app/funding.ts`, `src/app/panes/funding-pane.ts`).
**Tables on the panes** (`src/app/panes/pane-table.ts`). A pane with several things of one kind at one moment reads them in a table on itself, at the pointer's time or the newest: beside the plot where the columns right of it leave room (as many columns as fit, the last going first), else over its left end on a plate while the pointer is on the pane. The Depth pane's bands were the first; the Table switch in the header (on by default) now also gives the Funding pane every venue that lists the coin (funding per eight hours, its yearly rate, the premium where it is held; click a row to show that venue), the Open Interest pane each venue while venues are added together (its open interest in coins, its change over the candle, its share), and the Long/Short pane each venue's longs, shorts and their ratio.

## What stands out

One rule decides it everywhere: a value stands out when it exceeds the mean plus *k* standard deviations of the bars before it (default k = 2, baseline 72 bars; the bar itself never raises its own threshold, and nothing is flagged until a dozen bars exist). The **Highlights** panel sets k, the baseline and a master switch for every pane at once.

- **Volume** is a histogram along the bottom of the chart (toggle Volume): ordinary bars are dim, unusual ones are at full strength with a cap, a dashed line shows the threshold, a faint column marks the bar's slot up the whole chart, and the candle gets a glowing ring. The header line says how many sigma above its baseline the hovered candle is.
- **Depth** puts asks above the centre line and bids below it, as on the chart and in the order book, and draws the side with more liquidity brighter and the other dimmer, in proportion to the imbalance, and the readout names it ("asks +3.2%").
- **Order book** shows which side dominates the same way: at each row the bids and asks within that distance of the mark are compared (cumulative, the same comparison as the depth map), and the row's bars are drawn stronger when its side holds more and fainter when the other does, in proportion to the imbalance. A slim bar under the header shows bids against asks within the visible range as shares of their sum. Both follow the Highlights switch, and the zoom (wheel, price column) changes the distance they are read over.
- **Order book cues** (the **Cues** button in the book's header, on by default) light a venue's cell when the depth that venue shows at a price changes, the same strength and time for an addition and a decrease: the light runs out through the cell for an addition and back in for a decrease, so a removal shows even where dimming a dark bar would not. **Flash** chooses the look (Wash lights the cell, Rim only its outer edge, Deposit the layer an addition made, Signs nothing but the marks) and **Sensitivity** how large a change must be to light a cell (Calm: only the largest; Lively: the smaller ones too); a small signed mark beside each row keeps the last change for a few seconds (it is all reduced motion shows), and hovering a cell, the size column or a mark says what changed, how long ago and, where the trade tape covers it, what traded there around the same time (a removal of $1.5M beside $1.1M of orders that reached the row reads differently from one beside none). A change is the difference between two of that venue's own snapshots of its book, compared on the grid its far levels are merged on and only within about 6 % of the price, so a level that moves between rows because of the merge is not taken for one; it says nothing about orders (no cancel, no trade, no age: the exchanges do not send one). Light is limited so a busy book stays readable: the largest changes light first, every venue's largest before any venue's second, and the rest keep their marks. **Heat** is a strip under each venue's part of a level: the share of it that is estimated recent net increase (fading over 45 seconds), or its recent change. **Trade contact** ripples a venue's cell when a large market order reaches it (the trade tape; a ripple says an order met the depth there, not that the depth changed). The Cues panel also holds **Mirror**'s switch (since 2026-11-12, when it left the Panels deck): the hover comparison of both sides of the price on the book, the profile column and the liquidation column.
- **Open interest** adds up the perpetuals of every venue switched on by default (the pane's Venues select: All perpetuals or The chart market): Binance, Bybit, OKX, Bitget, Deribit and Hyperliquid, in coins. The Spot / Perp filter does not hide them: spot markets have no open interest, so under Spot the pane still counts the perpetuals, and so do NL/NS, the Long/Short pane, the bar statistics' oi chg, the Range readout and the open-interest profiles on the map. Binance and Bybit have days of history and OKX a day or two (the server reads it), the others build up while recorded; a candle's change is each venue's own change added up, so a venue whose readings start is not counted as positions opened, and NL/NS gives each venue's change to its own takers before adding them. It is drawn as a level: a step line carried forward from each sample, a dashed continuation to the newest candle, dots at real samples, and below it the change between samples with unusually large changes at full strength. Each change bar is split by who made it (the header's Bars: NL/NS, the default, or Net for the rise-and-fall colours): a rise by the new longs (buy colour) and new shorts (sell colour) it held, a fall by the shorts and longs closed, lighter, each part as much of the bar as its share of what opened or closed, grey for what went to no side; the readout and the popup list the parts. The few change bars much larger than all the others (more than 1.5 times the next; at most three, or a tenth of the changes in view where that is more; from 20 changes) are cut at the band's edge with a gap across them, so a flush no longer flattens the rest, and each one's popup gives its size. A reading from a venue's history closes the bar that ends at it, as a live reading does (until 2026-11-10 bars read from history showed the open interest at their start, a period late). If the market has no OI history (only Binance and Hyperliquid report it) a reference perp's series stands in, labelled. Open interest arrives on the venues' WebSocket streams where they have one (Bybit's ticker and OKX's open-interest channel, and on a server Hyperliquid's asset contexts); Binance, which publishes none, is read every 5 s, the others every minute. Each new reading moves the pane as it lands, the whole series is read again every 20 s, and the pane says how old the newest sample is. Zoomed out further back than the readings held (the chart's last 500 candles; 21 days at 1h), the line goes on faint and dashed from Bybit's own open-interest history, which reaches back years: read by the page straight from Bybit (the server's store holds days of it) in its five-minute to daily readings, no closer than 2 px apart, and scaled to meet the line where it starts, Bybit's reading there times the total over Bybit's (about ×6.7 on BTC, 2026-11-04, every venue counted on one side of its contracts). Bybit is one venue of several, so that part is an estimate of the total, marked ≈ in the readout and the popup and drawn without change bars; it is there while Bybit's perpetual is among the venues added together, and not in a replay (`src/app/panes/oi-long.ts`).
- **Trades** (the Trades button opens their panel; its lamp is lit while they show) puts bubbles on the chart at the time and price of each large trade (at least $25k), sized by notional, coloured by the side that took liquidity, only the biggest few hundred in view, with a glow for whale-size trades. They reach as far back as the recording (a day in the browser, a week on the server): a history answer carries the largest 5,000 orders of its window (BTC records 3,000 to 5,000 an hour), and a view zoomed well into a window whose answer was cut asks again for its smaller orders.

## The flow column

The column left of the map is the cumulative volume delta: for every exchange, what was bought at market minus what was sold at market, added up over time, **blue for spot and amber for perpetual** whichever way the money moved. The heatmap and the book are passive liquidity (what traders placed and may pull); this is active liquidity (what they did).

- **Rows.** An aggregate row on top (every spot lane added, every perpetual lane added), a price strip under it, then one row per exchange, ranked by gross volume over the ranking window (15 min, 1 h or 24 h) and re-ranked every few minutes so rows do not jump (or never, with Re-rank off). The ranking is strict about the count: an exchange with no volume does not fill a place, and any exchanges can be pinned (**Keep listed** in the gear: one toggle per exchange; they take the last places when they are not among the biggest). With the Spot or Perp filter on, the aggregate row says which kind it is and how many exchanges the filter leaves out (spot is only Coinbase and Binance, so "two of my eight" is the filter at work). A venue and its spot twin (`binance`, `binancespot`) are one exchange. An exchange with no trade in the last five completed minutes is flagged `!5m`.
- **Why an exchange is not a row.** Above the rows a notice names every exchange that has recorded flow and is not shown, and why: the Spot / Perp filter leaves it out (the button says **Show both**), its chip is switched off (**Turn on**), the number of rows asked for is smaller than the number of exchanges (**Show all**), it has not traded in the ranking window, or it has no order book on the map yet. Changing the filter or a chip makes the list again at once instead of waiting for the next re-rank.
- **Dot rows above the exchanges.** A strip of rows of small round lamps in a sunken well, an element of its own above the column's canvas (so the rows below it keep their layout): **taker flow** over the last 1, 5, 15 and 60 minutes, and **trade size** over the ranking window, one row per band of sizes (by default under $25K, up to $100K, up to $500K, and above). On every row buys fill from the left in the buy colour and sells from the right in the sell colour, the side that is ahead lit and the other dim, two grey lamps marking an even split; the number is the buy share (flow rows) or the band's share of the volume (size rows, with ten more lamps). The flow rows add the same instruments as the aggregate row, so the one-hour row says what ALL VENUES says; the sizes come from the footprint recorder's per-minute statistics, the only place they are kept (the flow has none). A row whose window was recorded for under nine in ten of its minutes wears an amber ring in place of its lamp, its dots are dimmed and the heading says `47/60 MIN`; the hover box always says how many minutes were recorded. The leading lamp of a size row lights for 0.6 s when a trade of that size prints (not with reduced motion, and the gear can switch it off). The size bands start at the Bar stats' limits (retail up to, whales from, the smallest trades on their own row) and are set in the gear under **Dot rows**. A server without `/api/v2/sizes` (an older one: restart it) leaves the size rows saying so while the flow rows go on. Not shown on a phone.
- **Labels are on the left**, in their own gutter, so nothing is laid over the ends of the lines on the right (the usual fault of CVD displays): `#rank EXCHANGE`, each lane's net flow over the ranking window with a dot in the lane's colour, then the exchange's share of all volume. Every line has its own vertical scale (compare shapes, not heights) and starts at zero at the left edge (a setting draws the running total since the history began instead).
- **Heights** follow the golden ratio (each rank is 1/φ of the one above, never below a readable minimum), the exchange's volume share, or are equal; the top row is always the tallest, and what does not fit scrolls (wheel or drag) under the pinned aggregate and price rows. Hover a row for a box: the lanes' running delta at the pointer, their net flow and buys against sells over the ranking window, the share. Hover the aggregate: spot and perpetuals moving apart (both sides over $2M and opposite) is said in words.
- **Time span:** Map (the map's own span up to now, starting where the flow starts when that is later, with "Flow recorded since 14:10" at the left: a map of days over a few minutes of recording would otherwise squeeze them into a column or two) or the last 5 min, 15 min, 1 h, 4 h or 24 h (which keep their length and say when recording began). All of them are drawn from one series at one-second resolution.
- **The price strip is a price a second**, the volume-weighted price of each second of the market on screen, recorded with the same trades as the flow lines (candle closes and marks fill in before the recording began, or for a market the recorder does not hold).
- **A shared time cursor.** Pointing at the column draws a vertical line at the same moment on the map, the depth, open-interest and tracker panes (and their readouts follow); pointing at any of them draws it on the column.
- **Colours.** Spot is blue and perpetual amber in every theme, on purpose: a hue says which market, never buying or selling, so it does not follow a theme's buy and sell colours. The one exception is a theme whose own buy and sell colours are near blue or amber (Colour-blind safe uses Okabe-Ito blue and orange), which gets reddish purple and bluish green so the lines do not read as direction.
- **Toggles.** Flow and Book in the top bar show or hide the two side columns (nothing is rebuilt); the column's own × does the same, and `[` and `]` hide or show the left and the right column wherever the panes stand. On a phone Flow is a dock tab. Settings live behind the gear in the column's header.

## Layouts and the places of the panes

Every pane has a place the person can change (`src/app/layout.ts`, `src/app/layouts/`). **The map and the panes that share its time axis** (Bar stats, Depth, Open interest, Delta, Long/Short, Funding, the Liquidity Tracker, Scripts) stand in the map's column, where their x axis is the map's: they can be moved among each other, never beside the map or above it. **The two panes with an axis of their own, the flow column and the order book, stand beside the map**, each on either side, alone or one over the other (they share the column's height by weights a splitter between them sets). Whether a pane is open stays one of the page's switches (`state.show`); where it stands is the plan (`DockPlan`: `left`, `right`, the width of each column or null where it follows the window, the weights). A closed pane keeps its place, so that opening it puts it back; a column with nothing open is a strip `--rail-w` wide with a tab for each pane it holds (`.edge-rail`, `.edge-tab`) and a column that holds none is not there.

**Moving.** Every pane but the map carries a grip (the handle), a ⋯ menu and, but for the Scripts pane, a × in its own header. A side pane keeps them on the first line, behind its name, whatever the width of its column (it can be made as narrow as 200 px with a mouse, 240 px on a touch screen): the "?" and the pane's first controls stand beside them where the column is wide (the flow column's span buttons from a column of 460 px, the order book's mode and Recenter from 490 px: one row for the flow column, two for the book; 545 and 580 px on a touch screen, whose buttons are bigger) and the rest wraps under (a title bar of its own above the header, the first version, had left the header's first line holding only the "?" and the settings key). A pane under the map carries them at the end of its header. The header is a handle all over where it holds no control. A drag (`#startDrag`) follows the pointer with a label and a mark (`.drop-mark`: a bar between two panes, or the strip along the window's edge where a column is not there); `src/app/layouts/dock-drop.ts` is the pure half (`dropTarget`: what a pointer at x, y would drop on), `dock-model.ts` the plan's arithmetic (move, swap the sides, nudge, which column is open, the widths a window allows: the columns never take more than 62 % of it together), both tested without a page. Escape or a drop anywhere else leaves the pane. On a phone nothing of this exists: the panes are tabs.

**Ready-made layouts** (`presets.ts`) are ways of working, not places: which panes are open, the order of those under the map and the share of the column they take, how wide the columns are as a share of the window, and the few chart switches the way of working is about. They are functions of the window (`buildPreset(def, {width, height})`), so the same layout fits a laptop and a large screen, and they never touch the timeframe, the heatmap's colours or any other setting: applying one lays the pane switches over the chart as it is (`settingsToApply`). *Default* is what a first visit shows (the flow column only from a window 1,500 px wide), *Map only* closes everything, *Order book* a wide book with Depth and the Liquidity Tracker under the map, *Order flow* a wide flow column with Delta and Bar stats and the footprint on, *Positioning* Open interest, Long/Short and Delta under a wide map with both columns closed, *Everything* every pane (for a large screen). "Swap the two sides" turns any of them over.

**Saved layouts** are kept in `hlm-layouts-v1` (at most 20) and in files (format `liquiditymapperfast-layouts`, version 1, read field by field: a file can come from anywhere). A layout saved without the chart's settings carries only the switches that open a pane (`PANE_SWITCHES`: Flow, Book, Bar stats, Depth, OI, Delta, L/S and LT, not the Scripts pane, which a layout does not decide), and applying one leaves every other setting and switch as it is (the footprint, the Volume profile and the rest); one saved with them (or by an earlier version, which always did) sets what it names. The arrangement keeps the fields the first version wrote (`order`, `heights`, `flowW`, `sideW`) and adds `dock`, so that an older page reads what a newer one wrote and a layout from before has the flow column left of the map and the book right of it. The page's own arrangement is `hlm-layout-v3` (it reads `hlm-layout-v2` once, which is left as it was); the layout last applied or saved and how the screen looked then is `hlm-layout-active-v1` (`active.ts`: the screen is compared with it by what the eye takes from it, so that a pane moved or closed since shows as "changed since"). `thumb.ts` sketches a layout's panes in a unit square, the same arithmetic the page lays itself out with.

Tests: `tests/dock-model.test.mts`, `dock-drop.test.mts`, `dock-presets.test.mts` (every ready-made layout in five windows from 1,024 to 2,560 px), `layouts.test.mts`, `shortcuts.test.mts`. The drag, the menu, the edge tabs and the panel were driven in headless Chrome over CDP, desktop, a touch tablet and a phone; the phone's arrangement is unchanged (every pane's box measured against the build before).

## The tour and the guide

Two ways in, for two kinds of reader. The **Guide** (`src/app/guide/`) is the long one and may grow as the page does: add what a reader needs to understand something, never text to fill a section or a second way of saying what is said (the header of `content.ts` says so). It was rewritten on 2026-11-10 after five weeks of features had gone in without it: 35 sections in seven groups (`Section.part` is the heading shown above the first section of a group), about 9,000 words, and a feature's "?" panel links to its own section (`guide:` in `help.ts`; add the section there when a feature gets one). **The search box** (above the contents list; [/] reaches it while the guide is open) answers in the contents list's place while something is typed: `search.ts` is a pure matcher over the guide's own text in the page's language (case, accents and width folded; a typed word is tried as the word, a beginning, a part of a word, a typo of one, and letters in order inside one; every word typed must be found; Chinese and Japanese are looked for as written with no typo room, Korean letter by letter so a syllable still being typed matches; a number is found whole or by its beginning, `10,000` and `10000` being one; if no one text has every word, a section with every word somewhere answers, worth less, and words found nowhere in the guide are dropped; question words such as what and how are not looked for), a section is answered by its best text with the match marked, and a result takes the reader to its paragraph and lights it (every rendered block, list item and key row carries `data-b`, `blockPath`). Esc clears the box before it closes the guide. On a narrow window the answer drops over the text. Its three words are in the page's packs (`Search the guide`, `Clear the search`, `Nothing in the guide matches that.`), and `tests/app-guide-search.test.mts` holds the matcher and what a visitor typing the feature names should reach. The **Tour** (`src/app/tour/`) is a minute: a modal that lights one part of the page at a time and says in a sentence or two what it is for. Nine steps on a desktop (the map, looking around, coin and timeframe, panels, the chart's layers, the flow column, the order book, layouts, the Guide), six on a touch tablet, four on a phone, which has tabs.

A step is data (`steps.ts`: what it points at by name, the side its card prefers, its words; a test holds every title to 30 characters and every body to 200). What a name points at is a list of selectors, resolved when the step is shown (`targets.ts`; a closed side pane is lit as its edge tab and the step says how to open it; a step whose target is not on the screen is left out). Where the card stands is pure arithmetic (`place.ts`: the side that has room, beside what is lit, never off the window, inside a target as big as the window). `tour.ts` is the modal: a `<dialog>` as big as the window, so the page under it is inert and Esc and the focus behave as in the Guide; the light is a hole in a dim layer that glides from step to step (not under `prefers-reduced-motion`); the arrow keys and PageUp/PageDown move, Tab goes round the card. It never changes the page: a folded top bar is unfolded for it and folded again (also when the tab goes in the middle of it), an open panel, menu, sheet or the Guide is closed first, each by its own door and not by a key pressed for it (an Esc would reach the chart as well: it puts a drawing tool away and unpins the Bar stats, so the tour's own Esc goes no further than the tour either), and a window that becomes a phone ends it. A start that fails (a browser that will not show the dialog) takes down everything it had begun.

**Offered once.** A visitor the tour was never offered to gets a notice under the top bar a moment after the page has drawn ("New here? A one-minute tour shows what everything is for.", with Take the tour and Not now; `invite.ts`, the notice the bar uses for a blocked venue). It never starts by itself, and it waits while a window, the Settings sheet, a panel or a menu is open (it asks again every few seconds for a minute, and is recorded as shown only when it is on the screen to be answered); the notices (a blocked venue, the coin list, this one) lie one under the other, each by what the one above measures (`Toolbar#stackNotices`), as a notice wraps on a phone. Declining says where the tour is found (the Tour button at the top right, or Settings on a touch screen) and it is not asked again, whatever the answer. What is remembered is `hlm-tour-v1` (`record.ts`: when it was shown, declined or left, and finished, and a version, so that a rewritten tour can be offered again to those who never finished the old one); a browser that keeps nothing is asked once per load. `?tour=0` leaves the offer out, for pictures and tests. The Tour button is the page's one filled button, beside the Guide in the page's own deck; the design note is `docs/proposals/tour-2026-10-31.md`.

## Coins

The **coin** button lists the coins on at least nine of the eleven browser markets (147 on 2026-10-07, BTC included; 62 are on all eleven), largest 24 h volume first, with a search. Choosing one loads the page again with `?coin=ETH`: new sockets, recorders and caches, so nothing of the last coin is carried over. The address and this browser remember it. `docs/coins.md` has the measurements and the decisions.

- **The list** (`coins.json`, built by `src/shared/coins.ts` from each market's own public list): names matched after units are converted (`1000PEPEUSDT`, Hyperliquid's `kPEPE` and Bybit's `SHIB1000USDT` are in thousands; OKX swaps by their contract value; Deribit's BTC and ETH perpetuals are sized in USD, its other coins are USDC perpetuals sized in coins), and a market kept only when its price agrees with the others' within 2 % (LIT on Binance spot is another token). A coin enters on nine markets and leaves below eight. The site's copy is rebuilt daily by the Pages workflow; a market whose list cannot be read there keeps its listings from the previous list (GitHub's runners are in the US, which Binance and Bybit refuse: measured on the first run, so their listings come from the repository copy). The copy in the repository is rebuilt with `npm run coins -- --out src/app/public/coins.json`. The local server builds its own each day into its data folder and serves it at `/coins.json`.
- **The server records BTC only.** A page it serves on another coin reads the exchanges itself, as the public site does.
- **Sizes follow the coin.** The recorders' floors (trades and absorption groups from $25K, map cells under $10K dropped from large columns, the size buckets) and every size setting (trade bubbles, liquidations, absorption, sounds and alerts, the Liquidity Tracker filter) are BTC's times a scale from the coin's 24 h volume against BTC's: ×1 (ETH), ×0.4 (SOL), ×0.1 (DOGE, PEPE), ×0.04 or ×0.01, following the square root of the ratio. Settings are kept as BTC's and shown scaled, so one setting serves every coin. The order book's Group steps move by whole decades to the coin's price, and prices are written with up to ten decimals.
- **Recordings** are kept per coin, BTC's in the IndexedDB database it always had and each other coin's in its own, recorded by one tab per coin; a coin not opened for a day has its database removed.
- **A market that does not list the coin** shows as such in the Venues picker and cannot be ticked; the venue choice stays one for every coin.

## Spot, perpetual or both

The Spot / Perp / Both control filters the enabled venues for the heatmap, profile, aggregated ladder, depth, LT and mirror. It never switches a venue on or off (chips that fall outside the filter are dimmed; a click on a dimmed chip shows that venue, which means the filter goes back to Both and the venue is switched on), it says so when it selects nothing, and executions (footprint, bubbles) are not filtered. Spot books show the walls that stand out far from the price; Binance spot (5000-level snapshot plus the diff stream) and Coinbase (full book) are the deep ones.

## Far liquidity

Zoomed out to a few percent either side of the price a heatmap has two problems: the venues' books have to reach that far, and thin walls become a pixel or less. Both are handled.

- **Reach.** Every book is merged into buckets that widen with distance from the mark (about 0.4 % of it): fine at the touch, then up to the recorder's grid step (always a whole-number divisor of it, so a bucket never straddles a recorded bin), then power-of-two multiples out to 16 steps, recorded in the bin of the bucket's farthest member. Levels beyond 50 % of the mark are dropped. This replaced a nearest-first cap of 2000 levels per side that stopped Coinbase's asks at +2.5 % while its sparse bids reached -20 %. `BOOK_LEVEL_LIMIT` (default 10,000) is the raw cap before merging.
- **Visibility.** Once price rows are under 15 px tall the raster is smoothed vertically with a Gaussian about 5 px wide (three box passes in the wasm kernel), so a thin wall becomes a visible band. Toolbar: Smooth auto / off.
- **Colour window** is taken from the visible raster only (15th and 96th percentiles of non-empty cells), so far walls are judged against the far book, not the dense touch.

The recorder keeps distance-adaptive buckets and drops bins under $10k, which holds a week of history for all venues to about 0.5 GB (68 MB a day; most venues sit at a few thousand bytes per minute, the deepest at about 10 KB).

## Trades and sound

The server keeps every venue trade of $25k or more (deduplicated, SQLite, one week), broadcasts them as they arrive and serves them by time window. Sounds have their own **Sound** panel, not the bar stats: a sound is a live event, bar stats are retrospective aggregates.

- A sweep that fills on several venues within a quarter of a second is one event. Its size selects a tier (Signal $50k, Surge $150k, Whale $400k, Leviathan $1.5M; thresholds are editable and stay ascending above $25k) and it sounds only if that tier is on (Whale and Leviathan by default). Buys rise in pitch and sells fall; a higher tier adds notes (one to four) and loudness.
- One AudioContext with a compressor, at most eight voices (extra notes are dropped, not queued), scheduled on the audio clock. Browsers keep audio locked until a click or key press, so the button shows an amber dot until then. Trades that arrive more than 2.5 s late (a throttled background tab catching up) are ignored.
- Options: volume, which venues count (all / spot / perp), a Test button per tier and side, and an optional chime when a candle closes on unusual volume. There is no liquidation sound: the feeds carry no real liquidation events.
- The decisions are recorded in `window.__hlm.sounds.log` so they can be tested without listening.

**Per panel.** Beyond trades, each pane can make one sound about something rare in it (Sounds panel, *Per panel*; `src/app/sound/alerts.ts`, the detectors in `alert-rules.ts` and `cvd/burst.ts`, all off by default): a **burst of taker flow** (an exchange's delta over 10 s is more than the chosen number of standard deviations from its own 30-minute norm, and at least a minimum; also marked on the flow column), a candle closing with a **big net delta** across the enabled venues, a **wall** (a level of at least a size, summed across venues in a 2 bp bin within 1 % of the price) appearing or being pulled without the price having come to it, the **balance tipping** (bids against asks within 1 %, with hysteresis), and an **unusual open-interest change** at a candle close (Highlights' rule). Nothing sounds from history, from the first ten seconds of a book, or within its cool-down, and no more than four sounds play in ten seconds. Buying rises and selling falls; each panel has its own register and wave. The decisions are in `window.__hlm.alerts.log`.

## Look

Each theme's frame (`html[data-frame]`, `src/app/chrome.css`, loaded last) sets the window language: square corners and one crisp outline in the Editor, softer corners in Paper, the classic desktop's pixel-drawn bevels in Bevel, double rules in Text mode. Glyphs are drawn rather than typed (the close crosses, the `?` marks, the language globe, the settings keys), so they sit in the middle of their box whatever the font. The tones are derived per theme in `src/app/theme.ts` (`chromeFor`, tested for edge visibility and text legibility; words on a tone, such as a warning or a caution, reach 4.5:1). Soft shadows, pill shapes and blur are not used: they cost the most to paint over canvases that repaint all the time.

**Waves** (the Waves lamp in the top bar's Alerts deck, beside Sounds, with its settings key; a switch and a **Wave strength** slider under Alerts in a phone's Settings; the Tape's own **Glass** choice is a different control) turns the bars and panels around the chart to glass, in any theme, and lets large orders light it and send waves across the screen. A large order lights the glass nearest where it traded, and the light gathers there, runs out as a ripple whose colours split and, for the largest, leaves a ghost mirrored through the middle of the screen, as a pair of binoculars throws from a bright light. It also starts a wave in a simulated wave field that runs across the whole screen, slows in the glass, is partly turned back by the splitters and fades at the edges; large changes in the flow column start waves of their own. A busy market holds its waves back by itself, so a cascade never floods the screen: orders of one side that come together at one place (within 48 px) make one wave, as one order of their summed size; waves start 8 a second at most (after a burst of 4), the largest first, each within 0.4 s of its first order or not at all; and the field keeps a running estimate of its own energy, on its own time (so a slow card's frames do not fool it), so that each new wave is let in smaller, and at a ceiling not at all, once it holds more than an ordinary day does at its busiest moments, or once its energy averaged over five seconds stays above an ordinary day's, as only a cascade's does; the busier it is, the sooner the echoes die. A large order on a quiet screen keeps its full height; an order of $1M or more (40 times the size that starts a wave) goes first and shows at half its height at least (up to 8 a second, while the field holds less than one and a half times its ceiling); and no side starts more than three waves in a row while the other has some waiting, so a crash's buys still show beside its sells. In a browser on a 1920 × 1080 desktop, a cascade of 150 orders a second went from 64 waves a second (192 started in any 3 s) to 8 (24), and the share of the screen showing a crest, averaged over time, from 25% to about 0.7% at the default strength (0.65 to 0.75% over two runs), where an ordinary day showed 0.39% before the setting: about as bright, over up to twice the area. The work the card does each frame is the same whatever the market does (at most sixteen substeps a frame); below 30 frames a second the field runs slower than the clock, so its waves last longer and a cascade shows about twice as much. The settings key opens the Waves panel: the same switch, and the **Strength** of the waves (0 to 100%, 50% at first, a fairly weak look: an ordinary day's crests on about a third of the screen they took before), on top of the limit and in the Tape's glass too; moving it sends a ring (one a second at most) from the middle of the page's glass so it can be judged on a quiet market. The glass also answers your hand: a pointer moving over it leaves a wake as fast as it goes, a key pressed in it sends a ring, and a splitter dragged pushes a wave before it. Your own touches are lit in the page's accent, never in a buy or sell colour, and nothing stirs while your hand rests. Physics carries the information: where the eye is drawn is where the market moved, and how far a wave reaches says how large the order was. It is drawn in WebGL behind the chrome, never over the data, and reduced motion keeps the glass and leaves the light out. A control whose fill is what its label is written on (the tour's filled buttons, a lit switch, a button held down, the Install mark under the pointer) keeps that fill on glass; the others take a see-through face of their own colour.

**The browser tab** says the price (GitHub issue #7): its title starts with the chart market's price and which way the candle under way is going ("75,903.4 ▲ BTC · LMF", ▲/▼ as the chart colours it, LMF short for LiquidityMapperFast), and its icon becomes that candle, drawn small on a dark square, so a pinned tab, which shows no title, still shows where the price is going (Safari keeps the page's own icon). Both are written from the price as it comes, never from a frame, so they move while the tab is in the background: the title at most once a second, the icon every three seconds, each only when it changes. Two switches, both on: the status bar's Tab key and Appearance in the Settings sheet (`src/app/tab-title.ts`).

## Scripts

Scripts are your own indicators: the Scripts switch in the Chart deck shows them, its settings key opens the Scripts panel where they are written, added from the examples, switched on one by one, imported and exported (a row lights while one of its buttons is under the pointer, so an Add or Delete at the far end is seen to act on its row; and the row under the pointer, or one of whose buttons has the keyboard, shows its script on the map behind the panel at once, the map stepped back under a veil of the page's colour: one drawn on the map at its prices, named first in the map's legend with its values, one that draws in a row of its own in a band at the map's foot; the list's scripts are worked out on a thread of their own as the panel opens, so a row shows within a frame or two of the pointer reaching it, and one that reads the order book is worked out when it is pointed at; the window opens against the page's right edge, over the order book, so the map stays in sight), and the pane under the map (the Scripts tab on a phone) is there only while a script that is on draws in a row of its own. Scripts read 10,000 of the chart's candles (2,000 on a phone; the panel's *Candles per script* offers 2,000 to 100,000), the chart market's own, read from the exchange once: more take longer the first time (a few seconds for 10,000 from Binance, about half a minute for 100,000 one-minute candles) and to run from the first candle, and the panel says while they are being read. A script is a short program run once for each candle of the chart, oldest first, that draws lines (`lineType=1`: a level across each candle), histograms, areas, bands, candles and marks (`mark(...)`: a label or shape above, below or at a value, whose text shows with the script's name under the pointer; crowded labels become dots) from what it reads: the chart's candle (`$price.open`, `.high`, `.low`, `.close`, `.volume`, `renderer.forming` while it is under way, and `renderer.last` on the newest candle it reads, closed or not, where a label of the newest value goes), what was bought and sold at market over the flow column's ALL VENUES markets (`vbuy`, `vsell`, in dollars) or over the markets it names (`source(vbuy, type=spot, exchange=BINANCE, quote=USDT)`; where the page did not record it, before it was opened or in a gap, the own candles of the set's Binance markets stand in, spot and perpetual added up, as far back as the scripts read: Binance's candles report their quote volume and the part of it bought at market (no other exchange's do), so a visitor's first look draws the flow scripts, a spot CVD as well as a perpetual one, over every candle a script reads; those are Binance's markets rather than all of them, so the numbers are smaller there, and `bar.recorded` is 1 where the flow was recorded and 0 where it is the candles'; a set with no Binance market stays unknown there, and so does a set while one of its Binance markets' candles is still being read or could not be read; a Binance market the page reads counts from the first look, before any trade of it is recorded), the liquidations (`lbuy` shorts liquidated, `lsell` longs liquidated; no candle reports them, so they are known only where recorded) and the change in open interest over the candle in dollars (`oichg`, as the open-interest pane counts it; loaded only for a script that reads it), and the order books the heat map adds up (`askdepth(usd)` and `biddepth(usd)`: the price at which that many dollars of asks above the candle's close, or of bids below it, are passed, each candle's book as the page recorded it at the close (its last minute, the latest recorded inside it where that one was not), every recorded bin's dollars spread evenly over its prices; `depthabove(usd)` and `depthbelow(usd)` the same over every dollar recorded at each price, bids and asks alike; `depthbooks()` how many books were recorded for the candle; `depthatclose()` false where the books are averages over the candle, from a server from before, whose one-sided walks read the side a move came from as thin; `src/app/script/depth.ts`, `depth-feed.ts`). The books are read only for a script that calls them, for the newest 1,000 candles at most and as far back as the recording reaches, the newest first, and handed to the scripts' thread once; after that only what can still change is read again (the candle under way and those not yet settled, every 30 s and as each candle starts; a book with nothing recorded yet is asked again every 3 s in its first two minutes), and the depth of the last few timeframes is kept so that a switch back has it at once. A browser recording answers in about 0.1 s; a server answers with its other recorded data, which on a busy one takes seconds to tens of seconds after a load or a timeframe switch (measured 2026-10-29: every request of a switch, the heat map's own columns included, took 1 to 15 s, against 0.1 s once it was quiet). Each script draws in a row of its own under the map, or on the map, where its plots on the price scale stand at their prices and the others on scales of their own, and the map's popup gives their values at the candle under the pointer (right of the newest candle, its newest values; a pane row's popup does the same), and the map's legend, under the candle's prices at its top left, lists each script drawn on the map with its colour and its values there (on a phone its name), up to six; a legend line and a pane row each have three buttons: an eye that hides the script (it still runs and alerts; the eye is struck through while it is hidden, and the choice is kept with the script), one that opens it in the Scripts panel and one that switches it off (it stays in the list); `$price.color = ...` colours the map's candles. A script that comes with the page also has a "?" among those buttons, first, and one beside its name in the Scripts panel's list and among its examples, that opens a short description in plain words: what it shows, how to read it, what it is good for and where it stops (`src/app/script/about.ts`, in every language). A script is the page's own by its id: a starter's is its key, and one added from an example starts with the example's key and two dashes, which no script of one's own can have, so an edited, renamed or exported one keeps its description (one added before ids carried the key keeps it while its text is the example's, word for word). `alert(text, sound=..., when=...)` lists an alert under the script's name and makes one of the page's sounds (chime, rise, fall, tick, or none for silent), through the Sounds switch and the cap the panels' alerts share: only for the candle under way or the last closed one, once a candle for each call and at most every 20 s, never for what was there when the script started and never in a replay (`src/app/script/alert-news.ts`). A script cannot make sounds of its own. The switch's lamp is amber while a script waits for its first answer (on a page whose own requests are many, that can take tens of seconds) and red when one stopped with an error.

The language is the indicator-script language other charting pages use, so most scripts written for them run here as they are, and their indicator files and workspaces can be imported: JavaScript's expressions and statements, `name = option(default=14, type=number|color|checkbox|text, label=...)` settings, a name set without `var` that keeps its value from candle to candle (from 0, `x[1]` one candle back), and stateful functions (`sma`, `ema`, `rma`, `sum`, `cum`, `cma`, `highest`, `lowest`, `last`, `linreg`, `stoch`, `pivot_high`, `pivot_low`, `avg_ohlc`, `heikinashi`, `ohlc`, `cum_ohlc`, `interpolate`). Not here: trade counts (`cbuy`, `csell` read NaN), single markets by name (`EXCHANGE:pair`), a chart library's series objects, `try`, `switch`, `for ... of`. A candle whose flow is known neither from the recording nor from Binance's own candles, or whose liquidations were not recorded, reads NaN and draws nothing, and the functions go on past it instead of being spoiled by it.

A script never runs as the page's JavaScript: its text is read by the page's own interpreter (`src/app/script/lang/`), on a thread of its own (`script.worker.ts`), and sees only its inputs and the functions of the language, never the page, the network or the page's storage. Each run has a budget of steps (and what a script makes, arrays and texts, is paid for in steps), so a loop that never ends or grows too large stops with its line and column, and a run that takes too long has its thread ended. A script runs again at most once a second, and less often while it is slow (for ten seconds after the market, timeframe, scope or venues change, as soon as what it reads lands, but never closer than twice the time a run takes); between two candle closes only the candle under way runs again. Scripts are kept in this browser (`hlm-scripts-v1` in its local storage for this page's address, each with the version of the language it was written for; nothing is sent to a server) and can be written to a file and read back from the Scripts panel, which is how they move to another browser or device. The Scripts window is sized by its lower corners, the left one taking its left edge and the right one its right (kept in this browser as `hlm-panel-sizes-v1`; a double click on a corner gives back the size it opens at), and a script's text then takes the room left in it. Copy for AI, in a script's editor, puts on the clipboard what an AI assistant needs to write or fix it: the language's rules and names, the script with line numbers (set apart as data), each error and warning with its code and place, what it last drew, in English whatever the page's language; the answer is pasted back and checked. The whole language is published at the site's root for people and assistants: `script-reference.md` (every error code with a script that meets it and its fix), `scripts.json` and `llms.txt`, all generated from `src/app/script/lang/reference.ts` by `npm run reference` (a test fails while they differ from it, while a function or plot of the interpreter is not described there, or while an error's example does not meet its code). The language is described as JavaScript-shaped, with what it does not have listed, and names no other product. In a browser that offers page tools to agents (WebMCP, `document.modelContext`), the open page also offers an agent in that browser eight tools (`src/app/agent/`, loaded only where the browser has page tools): `get_page` (coin, market, timeframe, newest candle), `get_script_language` (a summary and the reference's address), `list_scripts`, `get_script` and `read_script` (the person's scripts, how each last ran, its text a page at a time), `try_script` (runs a text once over the chart on a worker of its own, under the same limits, and says what it would draw or where it stops; nothing is kept or drawn), `propose_script` (opens the Scripts panel on a draft the person reads, then saves or drops; refused while they have changes not saved) and `set_timeframe` (what a timeframe button does; the page remembers it as it remembers that click). No tool saves, deletes or switches on a script, or reaches anything beyond the page; each answer is a small JSON object (at most 1,500 characters), and those that carry the person's scripts are marked as untrusted content. Browsers that do not have page tools need a switch or the page's origin-trial token for them. A browser that has never kept any starts with two (`src/app/script/starter.ts`), and the Scripts switch on (Karl, 2026-10-27; a save from before Scripts existed reads the new default, one that holds it off keeps it off): VWAP with bands on the map, on (Karl, 2026-10-28; a rolling volume-weighted average of the typical price over the last 48 candles, with bands 1.8 deviations wide; each candle weighted by the volume its exchange reports, as for the chart's VWAP, so it draws over every candle whether or not the page recorded it, and an untouched copy written by an earlier version, which weighted by the recorded flow and drew nothing where none was recorded, is brought to it), and a stochastic heat map in a row under the map, off until switched on (on from 2026-10-27 to 10-28; where the close stands in the range of sixteen windows, from 4 to 210 candles, one row of colour each, with their average). The heat map is coloured from the page's theme through `theme`, a script input (`theme.dark`, `.background`, `.text`, `.up`, `.down`): red-orange where the close is near the bottom of its range, blue near the top, and a neutral grey a little off the chart's background at 50 (the theme the pane draws in, a previewed one included), light ends on a dark chart and dark ends on a light one, its stops worked out in Oklab so that equal changes look equal on both sides and the two sides stay apart for the common colour-vision deficiencies (chosen with two independent reviews of the colour research; the earlier blue, see-through grey and orange was the same on every theme); a Twelve steps option bands it as the original did, a candle that was not recorded draws nothing, and the average is off-white on a dark chart and near-black on a light one. A heat map a browser kept unedited from the earlier version (its old colours as they were, which a save in the editor wrote down) is brought to this one (`updateStarters`; `starter-previous.ts` keeps the earlier text). They are kept only once the list is changed, a deleted one stays deleted, and its example brings it back; a browser that already kept a list keeps it as it is. The other examples (`src/app/script/examples.ts`): bar patterns (on the map, coloured from the page's theme: what each candle did to the range of the candle just before it in time (after a gap in the candles, or one with no prices, a candle has nothing to be compared with), inside, outside, up or down, and the patterns that follow from that, judged where the candle closes (the one under way as it stands): a breakout of an inside candle and a failed break, each with its break level and next level, a rejection (a candle that went past the end of the one before, closed back inside it and has a wick on that side of at least twice the rest of the candle) and an outside candle that closed beyond the one before it; the pointer on a mark gives its levels and its candle's flow, liquidations, open-interest change and where it stood against the day's, week's and month's opens (and the hour's on charts shorter than an hour); an alert, off by default, once a breakout or a failed break has closed; descriptive only, as no test has shown them to say where price goes next), depth bands (on the map: how far a fixed number of dollars, or a share of an average candle's volume, of the recorded books reaches from the close, up and down), buyer and seller VWAPs (on the map), liquidations that brighten as a cascade becomes unusual, volume anomalies, cumulative delta, spot and perpetual CVD, a delta histogram and the buy share. Adding a script or switching one on switches Scripts on.

## Drawing tools

**Draw** (in the map's corner beside Select, `D`) brings out a rail down the map's left edge, under the legend, with seven tools: a **level** (a line across the map at one price, or a ray to the right from its point), a **zone** (a box of prices over a stretch of time, which can run on to the right edge), a **trend line** (a segment, or run on past either end), a **vertical line** (a moment), a **note** (a few words pinned to a point, with a leader line), a **Fib retracement** (1 at its first point, 0 at its second, and 0.236, 0.382, 0.5, 0.618 and 0.786 between) and a **parallel channel** (a line through two points and its parallel through a third). Each point is a click (a tap on a phone): a press that moves pans the map as ever, so the map can be moved while a tool is armed; the step to take is said at the map's foot, with Cancel. One drawing, then the tool is put away, unless *Keep the tool* is on. Arming a tool puts away Range and VWAP anchoring, which take the next press too, and the map stops following the market from the first point. A click selects a drawing (inside a zone or a channel too); its handles move its points, its stroke moves it whole, and a press inside a zone still pans. A zone has eight handles, its four corners and the middle of each edge (six where it runs on to the right edge, which has no right side): the middle of its top or bottom moves a price alone and the middle of a side a time alone, so a box drawn from a wick can be pulled to a candle's body. The magnet works on whatever a handle is dragging, a price on the open, high, low or close of the candle under the pointer (a time on its centre), and on a level or an event line moved by its stroke; Alt frees it. An edge's middle is there where the edge is at least 28 px long in view (48 px for a finger). Beside the drawing selected a small bar sets its colour (the theme's text colour, blue, amber, the point of control's purple and the buy and sell colours, so it reads on every theme), its width, dashes, how far it runs, a label, an alert, lock, copy and delete, and says its figures: a level's price, how far the price is from it and what rests in the book's row there now (the rows the book profile beside the map shows), a zone's prices, height and length, a line's move. **Inspect** (a level or a zone) asks the Range tool about the zone's box, or about the level's row over the time on the map. A level's **alert** sounds, through Sound, when the price crosses or reaches it, once a minute at most.

**The magnet** (Off, Weak or Strong; **Weak from the first visit**, Karl's choice; the rail's magnet button changes it) acts only while a drawing's point is placed or dragged. Its targets are the open, high, low and close of the candle under the pointer (the candle whose body is nearest, beside the footprint's rows too), never a search across candles, and, while *Snap to liquidity walls* is on (the default), the walls of resting liquidity in the heat map's column under the pointer: the rows holding at least three times the median of the column's rows in view and more than their neighbours. Weak catches within 8 px (14 with a finger), Strong within 20 (28), and both let go only past one and a half times that, so a point between two targets does not flicker; the target caught is shown before the click (High 81,500, Wall $12M), and Alt held places freely (Ctrl or ⌘ and a drag is Range). A point is a time and a price, never a candle: another timeframe, a zoom or another market of the coin draws it where it was put, and a candle that changes later does not move it.

Drawings are kept in this browser, each coin's apart (at most 100 a coin and 1,000 in all), outside layouts, as the VWAP anchors are; a document written by a newer version of the page is left untouched. **Drawings** (the list button on the rail) holds the magnet and its walls, *Keep the tool*, *Show drawings*, *Lock all*, this coin's list (select and Find, hide, lock, delete), a file to save them all to and read back (added to what is held, new ids where ids are taken, nothing past the caps) and Delete all (a second press). Undo and Redo go a hundred steps back, each coin its own; another tab's save is read at once. Screenshots show the drawings but not the handles, the rail or the bar. During a replay drawings show but do not change. On a phone Draw is a key over the map's top right, the rail is a strip along its foot and the selected drawing's bar stands over it; a double tap does not recentre while a tool is armed, and holding still still scrubs the crosshair and never places a point (draw by holding, where a held stroke turns into the drawing it resembles, was left out: it would take over that gesture). `src/app/draw/` (`model.ts`, `geometry.ts`, `magnet.ts`, `controller.ts`, `paint.ts`, `bar.ts`), `tests/draw-*.test.mts`.

**Chart type** (the cell after the timeframes in the Time deck; pointing at a row of its menu shows it before it is chosen): **Candles** (filled, drawn as outlines while live trades show), **Outline candles** (every body an outline on a halo, so the liquidity under it shows through), **OHLC bars** and **Line** (the closes joined; the magnet then offers closes only), or **Hidden**: no price on the map, so the heatmap and the trade bubbles show with nothing on top, the type kept for when the price comes back. Hidden is `show.candles` off, which the Panels deck's Candles switch set until Karl folded it into this button (2026-11-12: a switch that only showed and hid the candles, beside a chart-type button that never said whether they were drawn), so saved pages and layouts mean what they meant. The button is lit while the price is drawn, as the timeframe in use is, and the Candle colours panel says when the price is hidden. Pointing at Hidden previews the map without the price; a preview changes what is drawn (and the drawn candles' length), while the price history and the countdown go by what is kept, so a type previewed while hidden draws only the chart's own candles. Each keeps a contrasting halo over the heat and breaks where candles are missing. Not offered: Heikin Ashi (its candles are averages, at prices that never traded, on a map whose point is where real prices are), the charts without a time axis (Renko, Kagi, line break, point and figure, range) and the filled ones (area, baseline, HLC area, columns), which would cover the heat. `src/app/chart-type.ts`. The menu's last row, **Candle colours…**, opens a panel that gives rising and falling candles a body, border and wick colour of their own (each the theme's until one is chosen; a filled candle's border and wick are the theme's edge, an outline candle's the body's colour, an OHLC bar is the body's colour alone; the price line, its tag, the legend's figures and the ladder's price row follow the body; a script's `$price.color` still wins), with a rising and a falling candle drawn in them as they are picked. Kept in this browser and with a saved layout; a colour hard to see on the theme is said so. `src/app/candle-colours.ts`, `src/app/candle-colours-panel.ts`. Zoomed out until the chart's candles would be narrower than two pixels (`CANDLE_LINE_PX`), the map draws longer ones instead of the line through the closes it drew before (a user, 2026-11-11): the shortest timeframe at least that wide, the Volume bars' rule (`stripTimeframe`), or the price history's bars where they are longer still; made of the chart's candles added up and, before them, the price history read at that length (`priceWindow`'s `candleMs`), a longer candle the chart's begin inside taken from the history or left out (`src/app/zoomed-candles.ts`). They are drawn in a few calls for all of them (a path a colour), in the candle colours, with no Highlights rings and no script colours; the legend names their length and gives the drawn candle's figures, the magnet catches it, and a click that places an anchor goes to its start. A line chart stays a line; another market's history stays the dashed line.

## Limits

- Venue books differ in how far from the mark they reach, which is what makes a venue look thin on the map, not the level count. Measured on BTC (October 2026, after distance merging): Coinbase about 35 % each side, Binance spot about 41 %, HitBTC, Phemex and Binance US up to the 50 % limit, Bitget about 75 bp, Bybit about 47 bp (it subscribes to `orderbook.1000`), Hyperliquid about 470 bp in 20 aggregated bands, OKX about 85 bp on the perpetual and 115 bp on spot (its 400 WebSocket levels near the price, then `books-full` beyond them, read every 15 s: `shared/far-book.ts`), Aster about 180-260 bp on the server the same way (REST depth 1 000), Deribit's whole book to the 50 % limit, Kraken and Bitfinex deeper since they take depth 1 000 (about 400 / 300 bp) and `len` 250, and the venues that only publish a shallow book (MEXC, Crypto.com, KuCoin 1-6 bp; Gate.io 5-6 bp, Poloniex 13 bp, HTX about 20 bp; Bitstamp about 30-70 bp) stop where they stop whatever the cap, because merging cannot recover depth a venue never sends. The ladder shades rows beyond a venue's reach in Single mode, and each venue chip's tooltip states its reach. BitMEX currently serves empty books to this connection.
- The Liquidity Tracker has no per-order data: its size filter applies to a venue's aggregated size at one price bin.
- The server is single-threaded: with 24 venues it needs roughly half a core (see `Research_Findings.md`). If it saturates, heavy API calls time out and executions are missed, which shows up as gaps in the footprint. Feed sockets run without per-message compression for that reason, so they use more bandwidth.
- Depth history starts when the recorder first runs; nothing is back-filled. Footprint likewise records only trades seen while the server is running.
- Open interest history comes from the server's own samples plus public history where the venue offers it; the public history is five-minute resolution, the server's own samples are one-minute.
- The history store (candles and open interest) stops writing while its file is over its 224 MiB budget; the OI endpoint then serves live samples newer than the stored bars, but history stays short until the file is pruned.
- Far-liquidity history builds up over time: a zoomed-out spot view is only as deep as the hours recorded since the full-depth books were recorded.
